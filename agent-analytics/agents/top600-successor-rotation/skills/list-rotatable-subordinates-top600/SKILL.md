# Сотрудники команды под ротацию (list-rotatable-subordinates-top600)

Скилл вызывается, когда пользователь хочет **узнать, кого из своей команды можно ротировать**. Является самостоятельным и начинает трек «Ротации».

## Входные данные

От пользователя ожидается (необязательно) **год ротации**. Свой ТН и ФИО пользователь не называет — тул получает их от сервиса.

## Алгоритм работы

1. Определяем год ротации из запроса:
   - назван конкретный год («в 2026 году») — передаём его в `rotation_year`;
   - год не назван — `rotation_year` не передаём;
   - назван относительный год («в этом году», «в следующем году») — вычисляем год от сегодняшней даты из системного промпта (этот = текущий год, следующий = текущий + 1) и передаём его в `rotation_year`.
2. Вызываем тул `get_rotatable_subordinates` (ТН пользователя не передаём — его подставляет сервис).
3. Разбираем результат:
   - вернулось `message` без `subordinates` — сообщаем пользователю, что сотрудников под ротацию (в указанном году) в его команде нет, и завершаем работу по скиллу;
   - вернулся список `subordinates` — переходим к шагу 4.
4. Формируем и возвращаем результат пользователю. **ОБЯЗАТЕЛЬНО сохрани заданную структуру ответа (не добавляй новых блоков и не убирай имеющиеся):**
   1. Заголовок одной строкой: «Сотрудники вашей команды, которым требуется ротация» и, если год задан, « в <год> году».
   2. Таблица в порядке из ответа тула. Колонки **СТРОГО**:
      - **"ФИО"** — `full_name` в виде ссылки на профиль: `[full_name](https://hr.sberbank.ru/platform/profile/<person_id>)`;
      - **"Должность"** — `position_name`;
      - **"Подразделение"** — `unit_name`;
      - **"Год ротации"** — `rotation_year`.
5. Предлагаем подобрать кандидатов на место одного из сотрудников списка:
   > «Подобрать кандидатов на место кого-либо из этих сотрудников? Укажите, кого именно»
6. Если пользователь выбрал сотрудника - переходим в скилл `search-rotating-top600`.
