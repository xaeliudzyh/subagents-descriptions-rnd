# Оформление отчётного ответа виджетом (answer-widget-top600)

Скилл определяет, **как выглядит отчётный ответ** агента преемников и ротаций ТОП-600. Отчётный ответ — это ответ, в котором есть данные подбора: список кандидатов, оценки соответствия, текущие преемники, сотрудники под ротацию.

## Когда применять

Применяй скилл, когда готовишь пользователю отчёт по данным тулов:

- отчёт подбора по названию роли (трек `search-by-role-top600`);
- отчёт подбора преемников для позиции (трек `search-successor-top600`);
- отчёт с кандидатами на позицию под ротацию (трек `search-rotating-top600`);
- отчёт со списком сотрудников команды, которым пора сменить роль (трек `list-rotatable-subordinates-top600`).

**Не применяй** к ответам без кандидатских данных: подтверждения назначения/добавления, уточняющие вопросы, отказы («подходящих людей не нашлось», «нет прав»), ответы вне компетенции агента. Такие ответы остаются обычным текстом, без блока `json-render`.

## Обязательный порядок работы

1. Собери данные тулов по методике трекового скилла (кандидаты, оценки, преемники, позиция).
2. **Прочитай этот SKILL.md до формирования текста ответа.**
3. Сформируй ответ: лид-фраза → виджет-блок → детальные оценки → вопрос трека.

Не формируй отчётный текст таблицами вручную: отчётная часть (позиция, преемники, лучший кандидат, полный список) всегда идёт виджетом.

## Правила данных

- **Точность.** Переноси значения из ответов тулов как есть: без пересчёта, без округления, без «улучшений». Балл 8.1 остаётся 8.1. Числовые поля (балл, год) передавай числами, а не строками.
- **Полнота.** Таблица содержит всех кандидатов из ответа тулов — отбор «топ-N» вместо полного списка запрещён. Строки идут в порядке убывания балла (первый кандидат списка — он же «Лучший кандидат»).
- **Ссылки на профили.** ФИО в таблице — person-ячейка колонки типа `person`: объект `{ "name": <ФИО>, "url": <ссылка> }`. Ссылка строго вида `https://hr.sberbank.ru/platform/profile/<person_id>` — person_id (UUID) из ответа тула; идентификатор сотрудника другой природы (employee_id) в ссылку не подставляй. Markdown-ссылки внутри ячеек таблицы не работают — не используй их. Если у человека нет person_id, передай в person-ячейке только имя, без поля url. Ссылки в карточках «Текущий преемник» и «Лучший кандидат» — тот же формат url.
- **Инициалы аватара.** Первая буква фамилии и первая буква имени кандидата (например, «Иванов Пётр» → «ИП»).
- **Служебная информация скрыта.** Не показывай пользователю внутренние имена полей тулов (`score`, `ml_score`, `oshs_position_id`, `employee_id`, `is_my_unit` и подобные) и служебный идентификатор позиции — их нет в интерфейсе HR-платформы, пользователь их не читает. Плитка «Позиция» показывает только название должности — без грейда; идентификаторы оставляй только в аргументах вызовов тулов.

## Адаптация под трек

Каркас и плитки фиксированы; данные слотов и колонки Table определяются треком:

| Трек | Заголовок Dashboard | Колонки таблицы |
|------|---------------------|------------------|
| Подбор по роли | «Кандидаты на роль „<роль из запроса пользователя>“» | `fio` (person), `position`, `department`, `score` (number, sortable) |
| Подбор преемников | «Преемники для <ФИО> — <название должности>» | `fio` (person), `position`, `department`, `score` (number, sortable) |
| Кандидаты под смену роли | «Кандидаты на позицию <название должности>» | то же + `recommended` — «Рекомендован по стажу в роли» («Да»/«Нет») |
| Список сотрудников команды | По формулировке трекового скилла | `fio` (person), `position`, `unit`, `rotation_year` (number) |

Слово «ротация» в пользовательском тексте не используется (правило трека) — формулировки бери из трекового скилла.

## Пропуск и дробление

- В подборе по роли в плитке «Позиция» — роль так, как её назвал пользователь (а не название, подобранное в ТОП-600). Плитки текущего преемника нет. Детальные оценки перечисли по баллу кандидата, без деления по совпадению подразделения.
- **Плитка без данных опускается.** Нет текущих преемников — плитки «Текущий преемник» нет. В треке списка сотрудников плитки «Позиция», «Текущий преемник», «Лучший кандидат» опускаются, остаётся только Table-плитка. Пропуск плиток не порождает новых блоков: в ответе не больше одного блока `json-render`.
- **Несколько преемников.** Если у позиции несколько текущих преемников, перечисли каждого в карточке (имя + ссылка на профиль).
- **Больше 30 строк.** Одна Table-плитка вмещает до 30 строк. Если строк больше, раздели список на дополнительные Table-плитки **внутри того же Dashboard** («Кандидаты, часть 2» и т.д.) — все строки должны попасть в ответ, новых блоков `json-render` не создавай. Всего в Dashboard не больше 8 плиток, в таблице не больше 6 колонок.

## Состав отчётного ответа

Ответ собирай строго в этом порядке:

1. Короткая лид-фраза: одним предложением скажи, что нашлось («Для позиции … подобрал 5 кандидатов»).
2. Виджет-блок `json-render` (ровно один).
3. Детальная оценка соответствия и неочевидные инсайты — обычным markdown-текстом после блока: почему у лучших кандидатов такие баллы, риски, замечания методики. Виджет визуализирует данные, но не заменяет разбор — детальные оценки из трекового скилла сохраняй полностью, не выбрасывай их.
4. Завершающий вопрос трека (например, «Назначить преемником кого-либо из кандидатов?») — если шаг трека его требует.
