# Визуализация сводного профиля (answer-widget-profile-essay)

Скилл описывает, **как оформить сводный профиль сотрудника** блоком
`json-render`. Сводный профиль — это краткий ответ на «что ты знаешь про
меня», «покажи мой профиль», «какие у тебя есть данные обо мне / о <ФИО>»:
по данным тулов в нём сразу несколько категорий — ФИО, должность и роль,
грейд и сегмент, структура подчинения, контакты, профессиональные теги,
интересы.

## Когда применять

Применяй скилл, когда сводный профиль (свой или другого сотрудника) уже
собран и его нужно показать пользователю: в ответе сразу несколько категорий —
кто такой, где работает, что за роль, что за структура, теги, интересы.

**Не применяй**, если сводного набора категорий нет: полное эссе по методике
основного скилла `profile-essay` (до 11 разделов), уточнение неоднозначности
ФИО («нашлось несколько — уточните, о ком речь»), отказ и «данных нет»,
короткий фактический ответ одним числом («какой у меня грейд» — «13»), сжатая
версия по просьбе («короче», «в трёх предложениях», «для выступления»). Такие
ответы оформляются по своим скиллам, без блока `json-render`.

Дисклеймер и строка источников относятся только к эссе, в сводном профиле их
нет.

## Порядок работы

1. Собери данные о сотруднике по методике основного скилла `profile-essay`,
   шаги 1–3 (определить сотрудника, память агента, карточка сотрудника).
2. **Прочитай этот SKILL.md до того, как начнёшь писать ответ.**
3. Собери ответ в том составе, что описан в разделе «Состав ответа».

Не рисуй сводный профиль вручную markdown-списками и таблицами: по этому
скиллу он всегда идёт одним блоком `json-render`.

## Шаблон

Шаблон — **один** блок `json-render`: Dashboard из пяти плиток «Профиль
сотрудника». Каркас копируй как есть, плейсхолдеры `<...>` заменяй реальными
значениями. Компоненты ограничены перечнем шаблона (**Dashboard,
DashboardItem, Card, Stack, Avatar, Title, Text, Divider, Tag**): другие не
изобретай, вложенность не меняй. Заголовок панели несёт сам Dashboard
(`props.title`), отдельный markdown-заголовок над блоком не ставь.

каркасе три — поставь столько, сколько нужно). Цвета бери разные из палитры
(green, blue, cyan, purple, orange, grey, yellow, teal, magenta, red); соседние
цвета могут повторяться, смысла у цвета нет.

Блок оформляй fenced-блоком с меткой `json-render`. Не оборачивай его в
дополнительные кавычки и не добавляй пояснений внутри.

## Правила данных

- **Точность.** Переноси значения из ответов тулов как есть: без пересчёта,
  округления и переименований. ФИО, должности, названия подразделений, почты и
  теги — слово в слово. Грейд 13 остаётся 13.
- **Структура — цепочка, а не выдумка.** Линейную структуру собери из уровней
  подразделений витрины, соединив их « → » от верхнего к текущему.
  Agile-структуру — так же из данных agile-подразделений. От себя в цепочку
  ничего не добавляй.
- **Аватар — инициалы из ФИО.** Только `initials` (первые буквы имени и
  фамилии из подтверждённого ФИО); фото по url не используй.
- **Пустые значения не показываются.** Нет внешней почты — нет строки «Внешняя
  почта»; нет тегов — нет плитки тегов; нет интересов — нет плитки интересов.
- **Служебная информация скрыта.** Имена витрин, таблиц и колонок,
  идентификаторы (`person_id`, `employee_id`) и прочие служебные поля
  пользователю не показывай, только пользовательские значения.

## Пропуск секций

- **Строка без данных в плитке опускается**, остальные строки плитки остаются.
- **Плитка без единой строки данных опускается целиком вместе с заголовком.**
  Если нет ни одной почты и сегмента, но есть ФИО, плитка «Личные данные»
  остаётся с ФИО и инициалами. Состав и порядок оставшихся плиток не меняются:
  «Личные данные» → «Должность и роль» → «Структура подчинения» →
  «Профессиональные теги» → «Личные интересы».
- **Подписи без значений не печатаются.** «Сегмент: …», «Категория: …»,
  «Грейд: …», «Роль в команде: …» ставь только если значение есть.
- В плитке «Структура подчинения» подпись и текст agile-структуры (и её
  разделитель) ставь только если agile-структура заполнена.
- Если какие-то секции пропущены, формат не меняется: оставшийся блок остаётся
  тем же `json-render`.

## Состав ответа

Собирай ответ строго в этом порядке:

1. Лид-фраза — одно предложение о том, чей профиль показываешь («Вот что я
   знаю о вас по карточке сотрудника»).
2. Один блок `json-render` — Dashboard из пяти плиток (без отдельного заголовка
   раздела над ним: заголовок несёт сам Dashboard).
3. Завершающая фраза — предложение развёрнутого портрета («Если хотите
   развёрнутый портрет с карьерным путём и достижениями — подготовлю эссе»).
