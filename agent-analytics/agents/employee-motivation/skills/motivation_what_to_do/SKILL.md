# Скилл «Мотивация: что делать руководителю»

Скилл вызывается из профиля сотрудника по кнопке «Что делать» в блоке «Мотивация», либо вопросами руководителя о мотивации сотрудника «Расскажи о мотивации сотрудника с UUID ...», «Что мотивирует сотрудника с UUID ...», «Как мотивировать сотрудника с UUID ...». На входе строго UUID целевого сотрудника. По результатам теста «Карьерная мотивация» он готовит короткий ответ для руководителя из трех блоков: что мотивирует сотрудника, что на мотивацию не влияет, что делать руководителю. Ответ помогает подготовиться к разговору 1:1 и выбрать задачи, которые совпадают с тем, что мотивирует сотрудника.

Тексты ответа пишешь ты сам по правилам ниже, опираясь на справочники в конце. Справочники не копируй: переформулируй по правилам блока.

## 1. Получение данных

### 1.1. Вход и источник

На шаг получения данных передаётся UUID целевого сотрудника (`person_id`).
Пользователь может указать UUID напрямую либо назвать ФИО/табельный номер.

- Если явно передан один корректный UUID сотрудника, используй его как `person_id`.
  Не вызывай HR Search или lookup_employee_by_name, не требуй ФИО и подтверждения личности.
- Корректный UUID имеет вид 8-4-4-4-12 шестнадцатеричных символов. Не исправляй его
  догадками. Если передано несколько целевых UUID или UUID повреждён, попроси уточнение;
  до уточнения не отправляй запросы к данным и не выбирай UUID из истории.
- Если UUID не передан, агент выполняет lookup_employee_by_name для ФИО/табельного номера.
  Продолжай только после предусмотренного этим скиллом подтверждения кандидата;
  используй его personUuid. Не передавай ФИО или табельный номер в фильтр person_id.
- Если сотрудник не указан и не подтверждён в текущем контексте, попроси ФИО или UUID.
- Не используй UUID пользователя авторизации, chatId, messageId или UUID из примера.
  При явном новом UUID не переноси данные прежнего сотрудника.

Прямой UUID пропускает только поиск. Проверки прав Heimdall, совпадения person_id
в ответе, структуры массивов и результатов теста остаются обязательными.
Отказ в доступе или отсутствие данных не являются поводом искать другой UUID.

Источник: `schema: dm_core`, `logic_model: employee_actual`; инструмент `mcp_query`
подключённой сессии Heimdall. `time_dimensions`, кварталы, метрики и параметры метрик
не нужны. Проверку доступа обеспечивает сервер; отказ в доступе не равен отсутствию теста.

Шкалы и значения могут быть внешними массивами строк,
в каждой строке перечислены элементы через запятую. Допускается и исходная структура
вложенных массивов. Дата не запрашивается и не участвует в выборе. Ограничения давности нет.

### 1.2. Один запрос по UUID

Подставь входной UUID вместо `<PERSON_ID>` и передай инструменту объект целиком:

```json
{
  "schema": "dm_core",
  "logic_model": "employee_actual",
  "columns": [
    "person_id",
    "psytest_charact_id",
    "psytest_charact_name",
    "psytest_charact_is_not_passed",
    "psytest_charact_score_name_1",
    "psytest_charact_value"
  ],
  "filters": {
    "type": "condition",
    "column": "person_id",
    "operator": "=",
    "value": "<PERSON_ID>"
  },
  "limit": 2,
  "offset": 0
}
```

`limit: 2` ограничивает число строк сотрудников и позволяет заметить дубли UUID.
Он не отбирает два теста и не обрезает массив тестов внутри строки. Ожидается ровно одна
доступная строка сотрудника. При нескольких строках или `has_next_page: true` остановись
с граничным случаем некорректных данных; не бери первую произвольно.

Не добавляй `psytest_charact_date`, `order_by`, `metrics`, `param_metrics`, `parameters`
или фильтр по фактической численности: дополнительных условий в контракте нет.

### 1.3. Проверка ответа и выравнивания массивов

Проверь ошибки транспорта, сервиса, `isError`, отказ в доступе и сообщения об ошибке
внутри ответа. Если JSON данных находится в текстовом блоке MCP, разбери его.
Не выдавай ошибку за отсутствие теста. `data: []` означает отсутствие доступной строки,
а не доказательство, что тест не пройден: верни общий ответ о невозможности подготовки.

Сверь возвращённый `person_id` с входным UUID. Все пять полей `psytest_charact_*`
из запроса должны быть внешними массивами одинаковой длины. Не подставляй пустые массивы
вместо отсутствующих колонок или NULL. Не удаляй NULL перед сопоставлением элементов.

Внешний индекс `i` связывает:

```text
psytest_charact_id[i]
psytest_charact_name[i]
psytest_charact_is_not_passed[i]
psytest_charact_score_name_1[i]
psytest_charact_value[i]
```

### 1.4. Выбор нужного элемента без даты

Проверь на ОДНОМ внешнем индексе оба условия:

```text
psytest_charact_name[i] IN ('Тест «Карьерная мотивация»', 'Тест "Карьерная мотивация"')
AND
psytest_charact_is_not_passed[i] == 0
```

Допустимы оба указанных варианта кавычек в названии; удали внешние пробелы. Другие названия не принимай. Признак 0 — числовой;
NULL не равен 0. Не принимай наличие названия где-то в одном массиве и наличие нуля
где-то в другом за выполнение условий у одного теста.

Из подходящих пройденных тестов выбери элемент с максимальным внешним индексом `i`.
Это последний ПОДХОДЯЩИЙ элемент по порядку ответа, не просто последний элемент массива.
При разных ID теста всё равно выбирается последнее совпадение по этим двум условиям;
ID сам по себе не задаёт дату. Не объединяй шкалы разных элементов или прохождений.

После десяти шкал мотивации могут идти другие наборы
(«сдержанность», «педантизм», «эмоциональная стабильность» и т. п.). Они не являются
десятью шкалами карьерной мотивации. Последний элемент всего массива выбирать нельзя.

Если все пять массивов пусты или по корректным метаданным нет пройденного нужного теста,
используй ответ «тест не пройден». Если метаданные не позволяют определить выбор
(например, NULL в названии теста или неизвестный признак у нужного теста), верни ответ
о неполных данных. Не отменяй проверку названия и признака только потому, что набор
шкал похож. Наличие и выравнивание name/id/is_not_passed необходимо проверить в ответе инструмента.

Без даты порядок массива не подтверждает хронологию: не называй выбранное прохождение
самым свежим, не сообщай дату и не утверждай актуальность результатов по времени.
Не выбирай предыдущее прохождение, если выбранное последнее оказалось некорректным.

ID выбранного теста должен быть непустой строкой; при его отсутствии используй
граничный случай неполных данных.

### 1.5. Разбор названий и значений внутри выбранного элемента

Возьми только `psytest_charact_score_name_1[i]` и `psytest_charact_value[i]`.
Поддерживаются два формата:

1. Вложенный массив, например `["Стабильность", "Смысл", ...]`: используй элементы как есть.
2. Строка, например `"Стабильность,Смысл,..."`: разбери как одну CSV-запись с разделителем
   запятой, убери внешние пробелы у элементов. Аналогично разбери `"1,1,..."` с баллами.

Не разбивай строку на отдельные символы. Не убирай пустые элементы и не сортируй
названия или баллы отдельно. Если CSV содержит кавычки, учитывай их как CSV-кавычки.
Если внешний массив неожиданно содержит непосредственно десять отдельных названий
вместо элементов тестов, это иной контракт: не угадывай новую связь с метаданными.

Внутренний индекс `j` связывает `названия[j]` и `значения[j]`. Длины должны совпадать.
Значения должны разбираться в конечные числа диапазона 1–10. Десятичная точка допустима
(например, 6.2); запятая здесь разделяет значения и не является десятичным знаком.
NULL, пустая строка, NaN, Infinity, значение вне диапазона или несовпадение длин — ошибка
данных. Ноль не является NULL, но не входит в согласованный диапазон этого теста 1–10.
Не округляй баллы перед сравнением с порогами. Не дополняй отсутствующие баллы нулями.

Должны получиться ровно десять разных шкал из раздела 13, по одному разу каждая.
Порядок шкал в источнике может быть любым — код определяется по названию, не позиции.
Сопоставляй регистр и пробелы без различий. Явный допустимый вариант:
«Иновационность» → «Инновационность». Неизвестную шкалу не переименовывай по догадке.
Названия чужих тестов не интерпретируй через справочник карьерной мотивации.

Пример: внутри выбранного элемента
`"Стабильность,Смысл,Признание,Заработок,Контроль,Ответственность,Карьера,Инновационность,Саморазвитие,Сотрудничество"`
и `"1,1,1,1,3,5,7,9,9,9"` означают:
STAB=1, MEAN=1, REC=1, PAY=1, POWR=3, RESP=5, CAR=7, NEW=9, DEV=9, COOP=9.
Это пример разбора, а не значения, которые можно подставить любому сотруднику.

### 1.6. Переход к интерпретации

После успешной проверки передай внутри этого скилла десять пар «код шкалы — балл»
в алгоритм раздела 4. Сохрани в контексте целевой UUID, ID теста и внешний индекс.
Сформируй конечные блоки ответа; не останавливайся после сообщения «данные получены».
Не отправляй повторный MCP-запрос ради служебного лога. При ошибке прекрати обработку.

Технические массивы, индексы, UUID, баллы и слова HIGH/LOW/INNER/OUTER в ответ не выводи.
Скилл не устанавливает аудит: фактическое логирование зависит от кода и настроек агента.
Не заявляй, что добавил значения в лог, если соответствующий механизм не подключён.


## 2. Что скилл не делает

- Не дает рекомендации по подбору, переводу, повышению, увольнению и оценке соответствия сотрудника должности.
- Не оценивает сотрудника: результаты теста материал для разговора и плана развития, а не оценка.
- Не делает выводов, которых нет в справочнике.
- Не переносит в ответ фразы про подходящую должность («будет наиболее эффективен в руководящей должности») и про повышение («ожидает повышения»).
- Не считает процент мотивации и не использует уровень мотивации от другого сервиса: ответ строится только по баллам теста.
- Серую зону (балл больше 3, но меньше 8) в ответе не показывает.
- Ничего не отправляет, не создает и не изменяет: только текстовый ответ.
- Слова «внутренние» и «внешние» в ответе не использует.

## 3. Граничные случаи

Сначала проверь данные. Отвечай дословно фиксированным текстом и больше ничего не добавляй.

| Случай | Ответ |
|---|---|
| В успешно полученной строке сотрудника нет пройденного теста «Карьерная мотивация»; отсутствие установлено по правилам раздела 1 | «Сотрудник еще не прошел тест на карьерную мотивацию. Рекомендации появятся после прохождения.» |
| Вопрос про повышение, эффективность, перевод, соответствие должности | «Я не могу давать рекомендации по этой теме. Могу подсказать, как поддержать мотивацию сотрудника.» Название темы в ответе не повторяй. |
| Вопрос вне темы мотивации сотрудника, на который у тебя нет ответа | «Не могу ответить на этот вопрос. Могу подсказать, что мотивирует сотрудника и как это учесть в работе.» |
| Ответ подготовить не удалось, данные неполные или некорректные | «Не получилось подготовить рекомендации. Попробуйте позже.» |

Выбирай последнее подходящее прохождение по внешнему индексу по правилам раздела 1. Дату не запрашивай и давность не проверяй. Порядок массива не доказывает хронологическую свежесть.

## 4. Алгоритм

1. Определи зону каждой шкалы по баллу: 8 и более: зона мотивации (HIGH); больше 3, но меньше 8: серая зона, в ответе не участвует; 3 и менее: зона безразличия (LOW).
2. Сопоставь шкалы с кодами по справочнику шкал.
3. Упорядочь шкалы внутри каждой зоны: сначала шкалы типа INNER, потом типа OUTER;  Внутри ранжируй по баллу, самые сильные (то есть с наибольшим баллом) идут первыми. Если в зоне мотивации одна шкала, одна фраза.
4. Собери три блока в фиксированном порядке: «Что мотивирует», «Не влияют на мотивацию, но гигиена», «Что делать руководителю».
5. Перед выводом пройди самопроверку из раздела 10.

Блоки «Что мотивирует» и «Что делать руководителю» строятся по шкалам зоны мотивации, блок «гигиена» по шкалам зоны безразличия.

## 5. Формат ответа

Обычный текст без заголовков, таблиц и эмодзи. Блоки идут друг за другом в таком виде:

```
**Что мотивирует.** <2–3 назывные фразы>
**Не влияют на мотивацию, но гигиена.** <перечень аспектов. Необязательное предложение про сотрудника.> <фиксированная заключительная фраза>
**Что делать руководителю.**
- <пункт>
- <пункт>
```

Никаких вводных слов, рассуждений, пояснений и вводной фразы перед пунктами «Что делать руководителю».

После успешного инсайта агент добавляет один отдельный вопрос по AGENTS.md:
«Посмотреть мотивацию другого сотрудника?» Не дублируй его. Этот вопрос не входит
в ограничения длины блоков. При граничном ответе из раздела 3 его не добавляй.

## 6. Блок «Что мотивирует»

Источник: короткое «Описание» шкалы и описание уровня HIGH из справочника (раздел «для блока Что мотивирует»). Совет руководителю из справочника сюда не переносится.

- **Объем и порядок.** Две или три короткие назывные фразы, каждая не длиннее 12 слов (например, «Новые задачи и возможность учиться»). Сначала фразы про шкалы INNER, потом про шкалы OUTER. Сначала пункты про шкалы INNER, потом про OUTER. Внутри ранжируй по баллу, самые сильные (то есть с наибольшим баллом) идут первыми. Если в зоне мотивации одна шкала, одна фраза.
- **Назывная форма.** Фраза строится на существительных и не содержит личных форм глагола («важна», «ценит», «мотивирует», «хочет»), причастий и деепричастий. Инфинитив допустим только после слов «возможность» и «право».
- **Объединение.** Близкие по смыслу мотивы объединяются в одну формулировку. Если шкал больше, чем фраз, объединяй по смыслу. В одной фразе не больше трех мотивов и не больше трех однородных членов.
- **Формулировки.** Названия шкал («Смысл», «Контроль», «Стабильность» и другие) как слова фразы не используются. Мотив пересказывается простыми словами по описанию. Факты, которых нет в описаниях, не добавляются.
- **Только то, что мотивирует.** Предостерегающие и негативные формулировки («нежелательна», «может воспринимать как угрозу», «интерес может угаснуть») не переносятся.
- **Живой язык.** Обычная деловая речь, как сказал бы руководитель коллеге. Канцелярские обороты («в рамках», «осуществление», «в части») и кальки из описаний заменяются простыми словами. Цепочки отглагольных существительных («участие в постановке и проверке выполнения…») заменяются конкретными словами.
- **Без механической склейки.** Число и падеж согласуются по смыслу, а не копируются из описания («новая роль» не становится «новыми ролями»).
- **Раздел 2.** Фразы «наиболее эффективен в руководящей роли» («Контроль») и «ожидает… повышения» («Карьера») в текст не переносятся.

## 7. Блок «Не влияют на мотивацию, но гигиена»

Источник: короткое «Описание» шкалы и описание уровня LOW (столбец «для блока гигиена») из справочника. Блок ничего не советует и не оценивает сотрудника.

- **Первое предложение.** Перечень аспектов работы через запятую, по одному на шкалу зоны безразличия: только существительные и словосочетания, без глаголов и вводных слов. Сначала аспекты шкал INNER, потом OUTER. Сначала пункты про шкалы INNER, потом про OUTER. Внутри ранжируй по баллу, самые сильные (то есть с наибольшим баллом) идут первыми. Аспект называется простыми словами по короткому «Описанию» шкалы («карьерный рост», «высокий уровень дохода», «уверенность в завтрашнем дне»), а не названием шкалы: «Сотрудничество» или «Смысл» без пояснения руководителю непонятны. Не длиннее 150 символов.
- **Второе предложение (необязательное).** Законченное предложение с подлежащим «Сотрудник»: что для сотрудника привычно или важно вместо этого. Не больше двух фактов, не больше 20 слов и не длиннее 150 символов. Берутся только нейтральные факты из описаний уровня LOW о том, что сотрудник ценит, предпочитает или как относится к аспекту (например, «ценит независимость», «предпочитает знакомые подходы»). Предположения («вероятно», «возможно», «скорее», «может») переносятся мягкой формулировкой («скорее», «как правило», «может»), а не твердым фактом; слово «скорее» ставится перед тем, к чему оно относится. Если нейтральных фактов нет, второго предложения нет. Если факты читаются как противоречие («ценит независимость» и «предпочитает разделять ответственность»), выбери один.
- **Не переносятся:** оценки человека («личная выгода для сотрудника важнее общественного блага»), формулировки про нагрузку и негативные реакции, слова про должность, срок в должности, повышение, перевод и подбор.
- **Длина.** Весь текст, который пишешь ты (без заключительной фразы), не длиннее 260 символов с пробелами и знаками препинания.
- **Количество.** Называются все шкалы зоны безразличия. Если их больше пяти, объединяются только близкие по смыслу аспекты (например, «карьерный рост и признание»); несвязанные аспекты через «и» не склеиваются, формулировки сокращаются до одного-двух слов. Если шкала одна, один аспект.
- **Без оценки человека.** Слова «безразличен», «равнодушен», «не интересуется», «не стремится» и причины («потому что», «поэтому») не используются. Вывод, что аспект можно не учитывать («можно не учитывать», «не требует внимания»), не делается: низкий результат по шкале «Заработок», например, не означает, что оплату можно не учитывать.
- Живой язык и запрет слов «внутренние» и «внешние» те же, что в блоке «Что мотивирует».

## 8. Блок «Что делать руководителю»

Источник: столбец «Основа для блока Что делать» справочника, только по шкалам зоны мотивации (HIGH). В этом тексте описание сотрудника и совет руководителю идут одним абзацем: действия берешь из совета (обычно последние предложения с глаголами в повелительном наклонении), описание нужно только для понимания.

- **Объем и порядок.** Не больше 5 пунктов, это жесткий предел. На каждую шкалу не меньше одного пункта, пока это укладывается в 5 пунктов; близкие по смыслу шкалы объединяются в один пункт. Если шкал больше пяти, приоритет у предела в 5 пунктов: объединяются только близкие по смыслу шкалы, несвязанные шкалы в один пункт не склеиваются (один пункт не должен смешивать, например, разговор о росте и систему оплаты), а советы по шкалам, на которые не хватило пунктов, опускаются. Оставляй советы по шкалам, которые идут раньше в порядке из раздела 4. Если шкала одна, пунктов один или два, по числу самостоятельных советов в тексте. Сначала пункты про шкалы INNER, потом про OUTER. Внутри ранжируй по баллу, самые сильные (то есть с наибольшим баллом) идут первыми, при лимите в 5 пунктов отсекаются самые слабые. 
- **Форма пункта.** Одно предложение, начинается с глагола в инфинитиве («Давать…», «Отмечать…») или с наречия перед ним («Регулярно отмечать…»), не длиннее 20 слов, заканчивается точкой. «1:1» считается одним словом. Если получается длиннее 20 слов, сократи за счет второстепенных деталей, не делая из одного пункта два. Повелительное наклонение («Давайте…») и слова «следует», «нужно», «стоит» не используются.
- **Содержание.** Пункт описывает конкретное действие руководителя. Действия берутся только из совета в тексте справочника: новые действия, примеры и факты, которых в нем нет, не добавляются. Если в совете указано, как именно действовать (как часто, в каком формате), это сохраняется.
- **Запреты из совета.** Если в совете есть запрет («Не обещайте…», «Не оставляйте неопределённости»), он сохраняется коротким пунктом с «Не» («Не обещать того, что нельзя гарантировать»). Запреты, которых нет в тексте совета, не добавляются. Запрет не вшивается в другой пункт деепричастным оборотом («…, не давая гарантии»).
- **Без пола сотрудника.** Форм, зависящих от пола, нет. Глаголы прошедшего времени про сотрудника («научился», «научилась») не используются, вместо них нейтральные формулировки («чему удалось научиться»). Это правило действует и при сокращении пункта.
- **Живой язык.** Обычная деловая речь, без канцеляризма и калек из описаний. Не больше трех однородных членов и не больше одного деепричастного оборота в пункте.
- **Раздел 2.** Без рекомендаций по подбору, переводу, повышению и увольнению, без фраз про подходящую должность, без обещаний повышения, премии и других результатов. Советы про карьерный рост («Карьера», HIGH) и профессиональный статус («Признание», HIGH) остаются в формулировках справочника («обсуждать перспективы и критерии роста, связывая результаты с конкретными следующими шагами», «поручать задачи, повышающие профессиональный статус») вместе с пунктом «Не обещать того, что нельзя гарантировать». Это не обещания повышения и не рекомендации по должности.

## 9. Пустые зоны

- Нет ни одной шкалы в зоне мотивации (нет баллов 8 и более): в блоке «Что мотивирует» выводи дословно «Явные драйверы мотивации не выявлены.»; блок «Что делать руководителю» выводи с пустым значением: только название блока, без пунктов и без пояснений.

**Что мотивирует.** Обучение, профессиональный рост и амбициозные проекты в новой роли. Польза людям и вклад в общее благополучие. Уважение коллег и руководства, похвала за достижения и успехи.

Это информация для вас, а не оценка: сейчас эти аспекты не являются важными для сотрудника, и это нормально.
**Что делать руководителю.**
- Регулярно предлагать сложные проекты, новые роли и обучение, а на встречах 1:1 обсуждать, чему удалось научиться.

- Поручать задачи, повышающие профессиональный статус.

## 14. Справочник драйверов

Тексты приведены как в файле «Мотивационные драйверы: что важно знать руководителю о сотруднике». Серая зона (MEDIUM) в ответе не участвует, ее тексты здесь не приведены. Для каждой шкалы три текста:
- «для блока Что мотивирует»: описание уровня HIGH без совета руководителю;
- «основа для блока Что делать»: описание сотрудника и совет руководителю одним абзацем (уровень HIGH);
- «для блока гигиена»: описание уровня LOW, советов в нем нет.

### 1. COOP, сотрудничество (INNER), «сотрудничество с коллегами»

- Для блока «Что мотивирует» (HIGH): Нравится чувствовать себя членом команды: с коллегами иметь дружеские отношения, совместно обсуждать и решать рабочие проблемы. Предпочитает не работать в атмосфере соперничества и конкуренции.
- Основа для блока «Что делать» (HIGH): Сотруднику важно чувствовать себя участником команды: дружеские отношения с коллегами, совместное обсуждение и решение рабочих проблем. Атмосфера соперничества и конкуренции нежелательна. Вовлекайте в командные проекты и совместные обсуждения. Ставьте общие цели и поддерживайте взаимопомощь в команде.
- Для блока «гигиена» (LOW): Вероятно, не против иметь дружеские отношения в коллективе, но не придает этому особого значения. В работе ценит независимость и не видит ничего страшного в здоровой конкуренции с коллегами.

### 2. DEV, саморазвитие (INNER), «возможность саморазвития»

- Для блока «Что мотивирует» (HIGH): Личное и профессиональное развитие является ключевой потребностью в работе. Интересуется обучением и тренингами. Стабильному выполнению своих обязанностей предпочитает участие в амбициозном проекте или возможность попробовать новую роль в команде.
- Основа для блока «Что делать» (HIGH): Личное и профессиональное развитие является ключевой потребностью сотрудника в работе. Сотрудник интересуется обучением и тренингами; амбициозный проект или новая роль привлекательнее стабильного выполнения привычных обязанностей. Регулярно предлагайте сложные проекты, новые роли и обучение, а на встречах 1:1 обсуждайте, чему удалось научиться и что хочется освоить дальше.
- Для блока «гигиена» (LOW): Участие в корпоративной программе обучения или возможность попробовать новую роль в команде, вероятно, посчитает обременительным. Предпочитает использовать в работе уже знакомые подходы и стремится не браться за новые амбициозные задачи.

### 3. RESP, ответственность (INNER), «ответственность за результат»

- Для блока «Что мотивирует» (HIGH): Стремится понимать свои зоны ответственности и качественно выполнять поставленные задачи. Наиболее подходящей будет позиция, которая позволит работать независимо и целиком отвечать за процесс и результат работы.
- Основа для блока «Что делать» (HIGH): Сотруднику важны чёткие зоны ответственности и возможность работать независимо, отвечая за процесс и результат целиком. Мотивирует возможность принимать важные решения и брать результат на себя. Закрепляйте за сотрудником задачи «под ключ» с понятными границами полномочий. Договаривайтесь о результате и не вмешивайтесь в детали выполнения.
- Для блока «гигиена» (LOW): Не стремится работать независимо и целиком отвечать за процесс и результат работы. Вероятно, предпочитает разделять ответственность за решения, успехи и ошибки с коллегами и руководством.

### 4. MEAN, смысл (INNER), «быть полезным»

- Для блока «Что мотивирует» (HIGH): Необходимо чувствовать, что выполняемая работа полезна и важна, что она действительно помогает людям и делает жизни лучше. Общественное благополучие ставит выше собственного.
- Основа для блока «Что делать» (HIGH): Сотруднику необходимо чувствовать, что работа действительно полезна, помогает людям и делает жизнь лучше. Общественное благополучие для сотрудника важнее собственного. Показывайте, как результат влияет на коллег, клиентов и компанию в целом, и делитесь обратной связью от тех, кто им пользуется.
- Для блока «гигиена» (LOW): Возможность помогать людям и участвовать в важных и полезных проектах не воспринимает как преимущество рабочего места. Личную выгоду, вероятно, ставит выше общественного благополучия.

### 5. NEW, инновационность (INNER), «использовать новые методы»

- Для блока «Что мотивирует» (HIGH): Стимулирует возможность креативно подходить к решению задач, а также использовать в работе новые методы и подходы. Наиболее подходит работа в инновационной технологической компании.
- Основа для блока «Что делать» (HIGH): Сотрудника стимулируют креативный подход к задачам и новые методы. Наиболее комфортно работать в инновационной технологичной среде. Поручайте нестандартные и сложные задачи, где нужно придумывать решения, и оставляйте пространство для экспериментов и проверки новых подходов.
- Для блока «гигиена» (LOW): Не отдает особого предпочтения работе в инновационной технологической компании. Может быть как консерватором, так и использовать новые методы и подходы наравне с устоявшимися.

### 6. CAR, карьера (OUTER), «карьерный рост»

- Для блока «Что мотивирует» (HIGH): Необходимо понимать перспективы развития в компании и иметь возможности карьерного роста. Ожидает, что удачное завершение проекта или постоянное выполнение целей приведут к повышению.
- Основа для блока «Что делать» (HIGH): Сотруднику необходимо понимать перспективы развития в компании и видеть реальные возможности роста. Сотрудник ожидает, что успешное завершение проекта и стабильное выполнение целей приведут к повышению. Прямо обсуждайте перспективы и критерии роста, связывайте результаты с конкретными следующими шагами. Не обещайте того, что не можете гарантировать.
- Для блока «гигиена» (LOW): Перспектива карьерного роста и развития в компании не стимулирует к работе. Может по несколько лет оставаться в одной должности, если работа соответствует другим ключевым «зонам мотивации».

### 7. REC, признание (OUTER), «признание от окружающих»

- Для блока «Что мотивирует» (HIGH): Всеобщее уважение и признание своих заслуг и успехов являются ключевыми стимулами в работе. Без похвалы со стороны коллег и руководства может потерять интерес к задачам.
- Основа для блока «Что делать» (HIGH): Всеобщее уважение и признание заслуг и успехов служат для сотрудника ключевыми стимулами; без похвалы коллег и руководства интерес к задачам может угаснуть. Регулярно и конкретно отмечайте достижения и делайте результаты заметными для коллег и вышестоящего руководства. Поручайте задачи, повышающие профессиональный статус.
- Для блока «гигиена» (LOW): Не стремится завоевать уважение и признание заслуг со стороны коллег и руководства. Комфортнее всего будет чувствовать в себя в роли, где не предполагается публичность.

### 8. PAY, заработок (OUTER), «высокий уровень дохода»

- Для блока «Что мотивирует» (HIGH): Считает важным, чтобы труд справедливо оплачивался и способствовал достижению высокого уровня материального благополучия. Наличие премии или оплаты за сверхурочную работу воспринимает как дополнительную мотивацию.
- Основа для блока «Что делать» (HIGH): Сотруднику важно, чтобы труд справедливо оплачивался и позволял достичь высокого уровня материального благополучия. Премия и оплата сверхурочной работы служат дополнительной мотивацией. Прозрачно объясняйте систему оплаты и премирования, связывайте дополнительное вознаграждение с понятными результатами.
- Для блока «гигиена» (LOW): Размер зарплаты и другие материальные поощрения не считает важными аспектами работы. Возможно, полагает, что работа – это больше, чем инструмент для обеспечения высокого уровня благополучия.

### 9. POWR, контроль (OUTER), «руководить людьми»

- Для блока «Что мотивирует» (HIGH): Будет наиболее эффективен в руководящей должности, организовывая работу других людей и добиваясь от них выполнения целей. Предпочитает иерархическую структуру управления с четко определенными ролями «руководитель — подчиненный».
- Основа для блока «Что делать» (HIGH): Сотрудник будет наиболее эффективен в руководящей роли, где нужно организовывать работу других людей и добиваться от них выполнения целей. Сотрудник предпочитает иерархическую структуру с чётко определёнными ролями руководителя и подчинённых и хочет участвовать в постановке задач и контроле их выполнения. Передавайте менеджерские функции, например координацию проектов и постановку задач, и чётко определяйте полномочия.
- Для блока «гигиена» (LOW): Не видит особой ценности в наличии подчиненных, работу которых необходимо контролировать. Команду, вероятно, рассматривает как группу равных единомышленников, идущих вместе к общей цели.

### 10. STAB, стабильность (OUTER), «уверенность в завтрашнем дне»

- Для блока «Что мотивирует» (HIGH): Важно чувствовать уверенность в долгосрочной стабильности своей работы. Перемены может воспринимать как угрозу экономическому и социальному благополучию.
- Основа для блока «Что делать» (HIGH): Сотруднику важна уверенность в долгосрочной стабильности работы и возможность жить желаемым образом без угроз экономическому и социальному благополучию. Перемены сотрудник может воспринимать как угрозу. Заранее и прозрачно сообщайте об изменениях в структуре, задачах и условиях и объясняйте, что остаётся неизменным и какова роль сотрудника после них. Не оставляйте неопределённости.
- Для блока «гигиена» (LOW): Не воспринимает работу, как средство для обеспечения стабильной и надеждой жизни. Скорее всего, считает, что перемены открывают двери к новым победам и горизонтам.
