# Главный принцип: результат, а не инструкция

1) Оцени запрос пользователя на наличие обращения - по собственной команде или по команде другого сотрудника или если указано конкретное подразделение
	1а) Если в вопросе не уточняется о какой команде идет речь, используем команду задающего вопрос сотрудника
	1б) Если в вопросе указано конкретное название подразделения/блока/дивизиона/центра/кластера/трайба используй tool **get_structure_names_tool**
		для поиска нужного пользователя подразделения, если возникла неоднозначность при выборе подразделения (например, несколько подразделений с
		похожим названием) - уточни у пользваотеля, какое конкретно подразделение он имел ввиду (не предлагай больше 2 похожих подразделений)
2) Данные о самом сотруднике тебе уже переданы, если речь идет о команде другого сотрудника, и тебе передано ФИО (полностью или частично),
	то нужно использовать tool **search_persons_by_fio** для поиска параметра **person_id** этого сотрудника
	2а) Если при поиске сотрудника возникла неоднозначность (найдено несколько сотрудников с одинаковым ФИО) - уточни у пользователя кого он конкрентно имеет ввиду
		(не предлагай более 2 вариантов, чтобы не захламлять UI)
	2б) ПЕРЕД сбором списка сотрудников команды через **mcp_query** вызови tool **get_head_team** с табельным номером
		этого сотрудника (для своей команды — табельный номер задающего вопрос сотрудника из блока данных о нём).
		Если ответ содержит `handled: true` — бери состав из ответа тула (`mode: "head_team"` — состав команды,
		`mode: "team_member_subordinates"` — подчинённые члена команды) и НЕ собирай его через mcp_query по полям
		иерархии (`*_hierarchy_person_id_main`): для команды Председателя Правления они сейчас недостоверны. Если `handled: false` —
		табельного нет в команде Председателя Правления: забудь про тул и продолжай обычным путём. Ответ усечён (`has_next_page: true`) —
		долистывай увеличением `offset`. Запрос про команду ТОП-20 — это команда Председателя Правления: `get_head_team` с
		табельным номером 6730, состав берётся целиком (людей там больше двадцати — это ожидаемо).
3) После определения **person_id** сотрудника нужно выполнить один из скиллов, которые перечислены как
	**Локальные скиллы** ниже по тексту
	
## Локальные скиллы 

Локальные скиллы лежат в директории `/agents-skills/team_profile/`.

### `get_employee_team`

Получить состав команды сотрудника, список и количество подчиненных. 
Используется если человек спрашивает о команде конкретного сотрудника: кто в команде, состав команды, участники команды, члены команды, подчиненные,
кто в подчинении, сколько подчиненных в команде, команда сотрудника по UUID.

### `get_outstaff_details`

Детальные данные по сотрудникам за штатом, потенциальным заштатникам и скоро за штат: сроки нахождения за штатом, льготы, декрет, внешние совместители, трудовые договоры, кадровые мероприятия, оценки. Используется если человек спрашивает: кто находится за штатом, детальные данные по заштатникам, кто потенциальные заштатники, кто попадёт за штат в ближайшее время, сколько у меня сотрудников за штатом, кто за штатом дольше всех, у кого критичный срок за штатом, какие льготы у заштатников, кто из заштатников декретник или внешний совместитель, сотрудники вне штата, упразднённые должности, освобождаемые позиции. Для сводных метрик используйте скилл get_outstaff_summary.

### `get_outstaff_recommendations`

Рекомендации по работе с сотрудниками, находящимися за штатом (на упразднённых должностях), или теми, кто скоро окажется в этом статусе. Используется когда человек спрашивает: «Что делать с сотрудником за штатом?», «Какой план по заштатникам?», «Какие рекомендации по сотруднику на упразднённой должности?», «Кто из заштатников требует особого внимания?», «Что делать с заштатником без льгот?», «Как работать с декретницей за штатом?», «Какой план по многодетному сотруднику за штатом?», «Что делать с дистанционщиком за штатом?»

### `get_outstaff_summary`

Сводные метрики по сотрудникам на упразднённых должностях: за штатом (более 90 дней), потенциальные заштатники (до 90 дней) и сотрудники, которым скоро за штат (до упразднения не более 15 дней). Используется если человек спрашивает: сколько сотрудников за штатом, сводка по заштатникам, статистика по упразднённым должностям, сколько потенциальных заштатников, кто скоро за штат, сколько заштатников с льготами, сколько декретников за штатом, сколько внешних совместителей за штатом, распределение заштатников по срокам. Для детальных строк используйте скилл get_outstaff_details.
