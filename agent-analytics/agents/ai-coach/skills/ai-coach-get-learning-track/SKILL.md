# Инструкция для агента: получение трека развития пользователя

## Когда использовать

Если необходимо получить:
- трек развития пользователя
- трек обучения пользователя
- ипр пользователя
- план развития пользователя
- индивидуальный план развития пользователя

---

## Используемый инструмент

- **MCP-сессия:** `pulse-personal`
- **Инструмент:** `app-learning-track.getAiLtrack`

---
## МНОГОШАГОВЫЙ ДИАЛОГ

Ты работаешь пошагово через вызовы основного агента. Контекст диалога
(предыдущие шаги и ответы пользователя) передаётся тебе в тексте задания —
**НЕ переспрашивай** то, что уже известно из контекста.

Если в ответе ты предлагаешь следующий шаг (изменить трек, создать трек,
перейти к подбору навыков) и ждёшь решения пользователя — задай вопрос/предложение
и жди ответа в следующем вызове. Если ты просто предоставил(а) информацию о треке
и дальнейшие действия не требуют ответа пользователя прямо сейчас — заверши ход
финальным ответом. Трек диалога движок ведёт автоматически.

---

## Параметры вызова

При вызове инструмента `app-learning-track.getAiLtrack` не передавай
**ни одного параметра**: трек текущего пользователя сервис определяет по
сессии сам, а любой переданный аргумент подменяет это определение.

- Параметр `trackId` **не передавать** (параметр должен отсутствовать в запросе).
- `person_id`, `employee_id` и любой UUID из задания — это **НЕ** `trackId`.
  Передача `person_id` в `trackId` даёт ложный `NOT_FOUND`.
- Если инструмент вызван с аргументами — результат **недостоверен**: повтори
  вызов без параметров, прежде чем сообщать что-либо пользователю.

---

## Интерпретация ответа

Ответ инструмента анализируется по JSONPath-выражениям.

Статус `NOT_FOUND` считается достоверным только для вызова без параметров.

Если трек есть (создан) предложи перейти
по ссылке https://hr.sberbank.ru/platform/growth/evolve чтобы начать проходить
трек или предложи изменить трек развития. Если трека нет - предложи создать
трек развития.

## Качество вывода пользователю

- При показе трека раскрывай конкретику: состав навыков, цель развития и
  текущий статус трека из ответа инструмента.
- Избегай общих и очевидных формулировок-заглушек («у вас есть трек»,
  «продолжайте развиваться» без пояснения сути).
- Вывод остаётся лаконичным и деловым: содержательность не увеличивает объём
  сверх необходимого.

---

### Трек развития **создан**

Условие выполняется, если **одновременно**:

- `$.success` равен `true`
- `$.data.trackStage.status` равен одному из значений:
  - `WAITING`
  - `COMPLETED`
  - `IN_PROGRESS`

**Действие агента:** считать, что трек развития существует и продолжить работу с данными из `$.data`.

---

### Трек развития **отсутствует**

Условие выполняется, если **одновременно**:

- `$.success` равен `true`
- `$.data.trackStage.status` равен одному из значений:
  - `NOT_FOUND`

**Действие агента:** считать, что трек развития ещё не создан

---

### Трек развития получить не удалось

Любой иной случай, в том числе:

- `$.success` равен `"false"`
- отсутствует поле `$.data.trackStage.status`
- статус имеет неожиданное значение
- произошла ошибка сети / таймаут / исключение

**Действие агента:** считать, что получить трек развития не удалось.
