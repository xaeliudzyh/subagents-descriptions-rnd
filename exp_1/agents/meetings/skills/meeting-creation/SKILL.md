# Meeting Creation Skill

Создание встреч/совещаний в корпоративном календаре через MCP-сервер
`pulse-personal` (Spine Notification Calendar).

## Цель

Когда пользователь просит создать встречу, совещание, назначить встречу или
проверить свободное время — обязательно используй этот скилл и тулы
`spine-notification-calendar.*` из сессии `pulse-personal`.

**Главный принцип: минимум уточнений.** Пользователь пишет коротко
(«поставь встречу с Ивановым»), а все параметры (дата, время, длительность,
формат, тема, почта организатора) ты добираешь сам по значениям по умолчанию.
Итог — **одна сводка с готовым вариантом и одним вопросом**.

## Доступные тулы (Spine Notification Calendar)

| Тул | Назначение |
|-----|-----------|
| `search_persons_by_fio` | **Резолв участников по ФИО в email.** Поиск сотрудника по ФИО или части ФИО — возвращает `personUuid`, ФИО, должность, **email**, телефон (до 5 человек). Единственный тул, превращающий ФИО в почту. |
| `spine-notification-calendar.get_slots` | Получить **слоты календарей** участников **по их почтам (email)** со статусами `FREE` / `BUSY` / `TENTATIVE` — по всему составу встречи сразу. Занято только `BUSY`/`TENTATIVE`; `FREE`, отсутствие слота и пустой список слотов — свободно (см. шаг 3). |
| `spine-notification-calendar.create_meeting` | Создать встречу/совещание: **онлайн** — флаг `createOnlineLocation=true`, сервер сам создаёт ссылку на **Jazz**; **офлайн** — непустой `location` (см. раздел «Формат встречи»). Описание (`body`) не передаём. |
| `spine-notification-calendar.get_meetings` | Получить **все встречи конкретного сотрудника по его почте (email)** — проверить результат создания. Работает ТОЛЬКО по почте; диапазон — минимум на целый день. |

> Если тула нет в текущем runtime-allowlist — НЕ выдумывай его имя и не вызывай
> его. Сообщи пользователю, что инструмент недоступен.

## Значения по умолчанию

Полная таблица дефолтов — в инструкции агента (раздел «Режим минимума
уточнений»). Для этого скилла важно: свободное окно считается **по всем
участникам**, поэтому дата и время по умолчанию означают «первое окно, свободное
у всего состава»; если общих окон нет — ближайший рабочий день (пн–пт) в
пределах 14 дней. Явное указание пользователя важнее любого дефолта.

## Workflow создания встречи

Ровно **4 шага**. Между шагом 1 и шагом 4 не должно быть промежуточных
вопросов пользователю — все данные собираются в одном проходе.

### Шаг 1. Резолв участников и организатора

- **Организатор — это текущий пользователь.** Его почта уже есть в системных
  данных о пользователе (блок с ФИО/person_id/employee_id/email). Бери её
  оттуда. **НИКОГДА не спрашивай у пользователя свою почту** и не упоминай
  системные данные. Если почты там нет — только тогда спроси одной фразой.
- **В задании должен быть готовый список людей.** Группы и роли («моя команда»,
  «подчинённые», «отдел», «программисты») ты **не разрешаешь**: если пришла
  формулировка группы вместо имён, не подставляй участников по догадке —
  сообщи, что состав нужно определить, и попроси список людей (это тот же
  единственный вопрос, других в ответе быть не должно). Состав в таких случаях
  определяет основной агент другим субагентом.
- **Участники.** Для каждого названного человека (ФИО + должность) вызови `search_persons_by_fio`.
  - **Проверь релевантность каждого результата.** Поиск работает по частичному
    совпадению и может вернуть мусор. Оставляй только тех, у кого **фамилия
    совпадает с запрошенной** (или отличается опечаткой/окончанием); кандидаты
    с посторонней фамилией, служебными подстроками и цифрами в имени («Имя
    Фамилия01401618 Отчество») — **нерелевантны, в список не попадают и в
    сводке не упоминаются**.
  - **Ровно один релевантный** → берёшь его, вопрос не задаёшь, блок
    альтернатив в сводке не показываешь.
  - **Несколько релевантных** → берёшь **первого** (топ-1) и продолжаешь как
    будто всё однозначно; остальных **релевантных** запомни, чтобы перечислить
    в сводке (шаг 4) и спросить «нужен другой?». **Не останавливайся** и не
    задавай отдельный вопрос про человека.
  - **Не найдено (или все результаты нерелевантны)** → спроси ФИО/почту
    (единственный допустимый вопрос на этом шаге).
  - **У выбранного (топ-1) пустой email** → **НЕ подставляй молча следующего
    человека**: это была бы встреча не с тем, кого просили. Покажи в сводке
    (шаг 4) остальных релевантных кандидатов с должностями и спроси «у
    выбранного нет почты, нужен другой?». Если кандидатов нет — попроси почту
    у пользователя. Не выдумывай почты.
- По одному человеку — **один вызов** тула: для нескольких участников сделай
  несколько вызовов (ФИО разных людей в один запрос не объединяй).
- Почты можно брать из контекста диалога, если пользователь их уже называл
  (тогда поиск не нужен).

### Шаг 2. Черновик встречи с дефолтами

Собери черновик без обращений к пользователю. Полная таблица дефолтов — в
инструкции агента (раздел «Режим минимума уточнений»); здесь — как их
применить:

1. **Дата** — завтра. Если пользователь назвал дату/день — берёшь его.
   - **Дата в прошлом** → это ошибка: не вызывай `create_meeting`, сообщи
     пользователю и предложи завтра (уточни год, если он явно имел в виду
     другой).
   - Пользователь назвал **день недели** без даты («в пятницу») → возьми
     **ближайший** такой день недели в будущем и укажи его в сводке как дату;
     отдельный вопрос про дату не задавай (пользователь поправит в сводке).
   - Пользователь назвал **диапазон** («на следующей неделе», «до конца
     месяца») → бери первый рабочий день периода с 09:00 и укажи в сводке.
2. **Время** — 09:00 МСК, длительность **30 минут** (точное время уточнится на
   шаге 3 по свободным окнам).
3. **Формат** — по разделу «Формат встречи: онлайн (Jazz) или офлайн»:
   место не названо → онлайн, место названо → офлайн. **Не спрашивай «онлайн
   или офлайн?»**.
4. **Тема** — сгенерируй из запроса; если пользователь назвал тему («обсудить
   бюджеты») — используй её.
5. **Описание (`body`)** — **не передавай и не придумывай**: без него сервис
   сам подставит «Встреча». В сводке — строка «Описание: — (можно добавить)».
6. **Участники и организатор** — почты из шага 1; организатора в список
   участников **не включай** (он организатор, а не приглашённый).

### Шаг 3. Проверка слотов

1. Вызови `get_slots` **одним запросом** с `attendees` = организатор (текущий
   пользователь) + **все** приглашённые. Диапазон — от начала предлагаемого дня
   до конца следующего рабочего дня: широкий диапазон избавляет от повторных
   запросов.
2. Ответ — **слоты календарей участников с их статусом**; полная трактовка
   статусов — в `AGENTS.md` (раздел про свободные окна). Коротко: `BUSY` и
   `TENTATIVE` — занято; `FREE`, отсутствие слота и пустой список слотов —
   свободно (пустой список = участник свободен на весь диапазон). Свободное
   окно = непрерывный отрезок, где у **каждого** участника либо нет слота, либо
   слот `FREE`; одного `BUSY`/`TENTATIVE` у любого участника достаточно, чтобы
   окно не годилось. Окно подходит, если его длина ≥ длительности встречи
   (по умолчанию 30 минут).
3. Приоритет выбора: **завтра**, внутри дня — **самое раннее окно с 09:00**;
   если завтра общих окон нет — **ближайший рабочий день (пн–пт)** в пределах
   14 дней, самое раннее окно с 09:00. Запомни **до 4 следующих общих окон того
   же дня** (после выбранного), чтобы показать их в сводке.
4. Если окно, которое просил пользователь, занято — не создавай встречу молча:
   предупреди в сводке и предложи ближайшие общие свободные окна. Если
   пользователь **настаивает** на занятом времени — создавай на нём (жёсткое
   правило 4).
5. **Пустой список слотов — это свободный участник, а не отсутствие данных.**
   Окна по нему не ограничиваются. **Запрещено** писать «нет данных о
   занятости», «подтвердить свободное время не могу», «уточните у участника
   напрямую» и предлагать окна только по своему календарю.
6. **Окно свободно у всех — обязательное условие.** Окно, свободное только у
   Вас и занятое у приглашённого, вариантом не является: это встреча на чужое
   рабочее время.

### Шаг 4. Сводка и единственный вопрос

Покажи сводку по шаблону ниже и задай **один** вопрос — подтверждение
(или, если есть тёзки, вопрос про человека + подтверждение в той же сводке).
Больше ничего не спрашивай: тему, время, длительность, формат и почту
организатора пользователь может изменить одной фразой, если захочет.

После ответа «да / подтверждаю / создавай / ок»:
1. Повторно вызови `get_slots` **на целевое окно** этого дня **по всем
   участникам встречи** (организатор + приглашённые) — обязательная финальная
   проверка (окно могло занять у любого из них).
2. Вызови `create_meeting` с параметрами из сводки.
3. Сообщи результат — только то, что реально произошло.

## Шаблон финальной сводки

```
Готов создать встречу:

**Тема:** Встреча с Ивановым
**Когда:** 3 ноября (вт), 09:30–10:00 МСК (30 минут)
**Формат:** онлайн, ссылка Jazz (создастся автоматически)
**Участники:** Петров Пётр Петрович (главный специалист)
**Описание:** — (можно добавить)

По фамилии Иванов есть ещё подходящие — если нужен другой, скажите:
Иванов Иван Петрович — руководитель отдела
Иванова Мария Сергеевна — ведущий инженер

У Вас и участников свободно на этот день: 11:00–11:30, 14:00–14:30, 16:30–17:00.

Подтверждаете создание? Могу изменить время, длительность, тему, участника или формат (переговорка).
```

Правила оформления сводки:
- **соблюдай политику формата ответа** (раздел «Как писать ответ» в инструкции
  агента): без технических названий, о пользователе — только «Вы»/«у Вас», его
  ФИО не указывай, организатора строкой не выводи (это он и есть);
- поля — жирным заголовком, значения обычным текстом;
- дата — и число, и день недели; время — с поясом «МСК» и длительностью;
- **список альтернатив — без нумерации**: только ФИО и должность, каждая строка
  с новой строки (нумерация создаёт впечатление «всего N»);
- **формулировка счётчика** — «По фамилии <Фамилия> есть ещё подходящие — если
  нужен другой, скажите:». Не пиши «найдено ещё N сотрудников»: N не посчитать
  корректно, а часть результатов тула может быть нерелевантна. **Никогда не
  выводи цифру количества альтернатив**;
- если релевантных альтернатив нет — блок целиком **не показывай** (и не пиши
  «найдено несколько», если релевантен только один);
- **фраза про свободные окна зависит от числа приглашённых участников**
  (организатор в счёт не входит): «У Вас свободно…» (участников нет) /
  «У Вас и участника свободно…» (один) / «У Вас и участников свободно…»
  (два и больше). **Слово «обоих» запрещено** — оно верно только для двух
  человек, а фраза нужна для любого состава;
- **заглавная в «Вы/Вас/Ваш» — только когда речь о пользователе в единственном
  числе** (в «У Вас и участников свободно…» — с заглавной, потому что «Вас»
  относится к пользователю); групповые обороты («вы оба», «у вас всех») не
  используй;
- если предлагаемый день отличается от завтра — одной фразой поясни причину
  («завтра свободных окон нет, ближайший рабочий день — 5 ноября, ср»);
- свободные окна — **только за предложенный день**, до 4 штук, и это
  **отрезки, свободные у всех участников** (Вы + каждый приглашённый), а не
  только в Вашем календаре;
- если время пользователя было занято — так и напиши и покажи варианты;
- офлайн-встреча: вместо «Формат: онлайн» → «Место: переговорка 5-12».

**Если у выбранного (топ-1) нет почты** — тот же шаблон, но вместо строки
«Подтверждаете создание?» — вопрос про замену, и без финального «подтверждаю»:

```
У выбранного сотрудника (Иванов Иван Иванович — ведущий аналитик) не указана
почта, поэтому приглашение ему отправить не получится. Есть другие подходящие:
Иванов Иван Петрович — руководитель отдела
Иванова Мария Сергеевна — ведущий инженер

Нужен другой участник? Или пришлите почту вручную.
```

Пример ответа на «поставь встречу с Ивановым» — это ровно текст шаблона выше
(одна сводка, один вопрос, ни одной промежуточной анкеты).

**Эталон поведения (сценарии приёмки):**
- «Поставь встречу с Ивановым завтра» → один поиск по ФИО, один `get_slots` по
  всему составу, одна сводка по шаблону; вопросов про тему, длительность и
  формат нет, в ответе ровно одно вопросительное требование.
- Пустой список слотов у участника → он свободен на весь диапазон; формулировок
  «нет данных о занятости» / «уточните напрямую» в ответе нет.
- Несколько тёзок → топ-1 и блок альтернатив «ФИО — должность» **без нумерации
  и без цифры количества**; люди с другой фамилией не упоминаются.
- Группа вместо списка («встреча с моей командой») → состав не подставляешь,
  просишь список людей (единственный вопрос), поиск по структуре не запускаешь.

## Правила поведения

### Жёсткие правила

1. **Не спрашивай больше одного вопроса за ответ** (см. «Режим минимума
   уточнений» в инструкции агента). Вопросы про тему, дату, длительность,
   формат и почту организатора запрещены — это дефолты из сводки.
2. **ОБЯЗАТЕЛЬНО получи явное подтверждение пользователя ПЕРЕД каждым вызовом
   `create_meeting`.** Покажи сводку по шаблону и спроси прямо. Вызов тула без
   явного согласия — ошибка скилла, даже если слот свободен и все данные есть.
3. **Перед КАЖДЫМ вызовом `create_meeting` заново выполни `get_slots`** на
   целевой интервал по всему составу (организатор + все приглашённые) и сверь,
   что ни у одного участника нет в этом интервале слота `BUSY` или `TENTATIVE`
   (`FREE` и отсутствие слота — свободно). Не полагайся на ранее полученные
   слоты, если менялся состав или прошло время.
4. **Если время занято** — предупреди в сводке и предложи ближайшие окна,
   свободные у **всех** участников (окно, свободное только у Вас, — не
   вариант); если общих окон на день нет — так и скажи и предложи ближайший
   рабочий день из проверенного диапазона. Если пользователь **осознанно
   настаивает** («всё равно создай», «неважно, создавай») — создавай на занятое
   время, не блокируй создание после предупреждения.
5. **Не сообщай «встреча создана», если создание не произошло.** Сообщение
   должно точно отражать факт: либо «создана на <время> <тема> <участники>»
   (если на занятое время — отметь это), либо «время занято, предлагаю: …».
6. **Перед созданием собери ВСЕ данные:** тема, почты организатора и всех
   участников, согласованное время, длительность. Нет данных — задай **тот
   единственный вопрос**, которого не хватает (см. закрытый список случаев в
   инструкции агента).
7. **Никогда не выдумывай почты, слоты и id.** Единственный источник занятости —
   `get_slots`; свободные окна выводи только из него.

### Формат встречи: онлайн (Jazz) или офлайн

- **Место НЕ указано → онлайн** (по умолчанию): `createOnlineLocation=true`,
  `location` НЕ передавай. Сервер сам создаёт ссылку на **Jazz**; ссылку из
  ответа обязательно покажи пользователю.
- **Место указано → офлайн:** передавай `location` = указанное место,
  `createOnlineLocation` не передавай (при непустом `location` сервер флаг
  игнорирует).
- **Явная просьба онлайн** («созвон», «онлайн-встреча», «звонок», «Jazz») →
  то же, что по умолчанию.
- **Не задавай отдельный вопрос «онлайн или офлайн?»** — формат показывается
  в сводке, пользователь правит его при необходимости.

### Обычные правила

- **Понимание времени.** Вход — ISO 8601 со смещением (`+03:00` МСК или `Z`
  UTC), шлюз приводит всё к UTC. Выход календаря — всегда UTC (`Z`).
  Пользователю называй время в МСК и указывай пояс. **НИКОГДА не передавай
  время без смещения** (`2026-11-03T09:00:00` — ошибка; правильно
  `2026-11-03T09:00:00+03:00`), даже для полуночи и конца дня.
- Если создание вернуло ошибку (например, слот занялся в момент создания) —
  покажи понятную формулировку **без кодов и текстов исключений**, снова проверь
  `get_slots` и предложи ближайший свободный слот.
- Результат проверяй через `get_meetings` по почте организатора только по
  необходимости, диапазоном **минимум на целый день**: на узком окне ответ
  может быть пустым, и это не значит, что встреча не создалась.
- Если нужно изменить существующую встречу — переключайся на скилл
  `meeting-update`.
