# Профиль агентных навыков сотрудника по табельному номеру

Возвращает уровни шести агентных навыков одного сотрудника (по витрине
`stable.agentic_skill_level`) и параметры использования GigaCode за
последнюю дату расчёта.

## Когда использовать

- Пользователь называет сотрудника (табельный номер `tn`) или спрашивает
  про себя и хочет увидеть его агентные навыки.
- Пользователь называет сотрудника **по ФИО** и хочет его навыки — сначала
  резолв `tn`/`employee_id` через референс `lookup_employee_by_name`
  (готовый `mcp_query` по `dm_core.employee_actual` из системного промпта),
  затем профиль.
- Вопрос про уровень навыка (prompting, prompt engineering, context
  management, creating tools, creating skills, agents team) конкретного
  человека.
- Вопрос про использование GigaCode: доля ИИ-кода, agentic coding,
  частота использования, обучение (Agentic Coding / AI PDLC / GigaCode).

## Алгоритм

1. **Определи охват.** Витрина адресует сотрудника ТОЛЬКО по `tn`, других
   идентификаторов в ней нет.
   - **По табельному номеру** (`tn`): если спрашивают про себя — бери `tn`
     из контекста (у пользователя в данных есть его `tn`); если его нет —
     уточни. Если называют сотрудника с `tn` — используй его как есть.
   - **По ФИО**: если пользователь называет человека по ФИО — сначала
     резолв через референс `lookup_employee_by_name` (готовый `mcp_query`
     по `dm_core.employee_actual` из системного промпта), получи из ответа
     `employee_id` (`tn`) сотрудника. При неоднозначном результате
     (несколько человек) уточни, кого имел в виду пользователь, показав
     список с `employee_full_name` и `employee_id` каждого.
2. **Выполни готовый запрос** через `mcp_query`, подставив значение `tn`
   в фильтр. Не меняй структуру фильтра и набор полей.
3. **Обогати данные.** Получи ФИО, должность (`position_name`) и блок
   (`fblock_name`) сотрудника из `employee_actual` тем же запросом резолва,
   что и для ФИО (`employee_id = "<tn>"`) из системного промпта. Витрина
   даёт только `tn` — имя и должность бери отсюда.
4. **Собери ответ**: ФИО, должность, блок, табельный номер, уровни всех
   шести навыков, роль, область экспертизы, долю ИИ-кода за текущий месяц,
   частоту использования. Поясни, что уровни — это числовая шкала
   поставщика.

## ГОТОВЫЙ ЗАПРОС

```json
{
  "schema": "stable",
  "logic_model": "agentic_skill_level",
  "columns": [
    "tn", "calc_date", "role_main", "role_2", "expertise_area",
    "n1_prompting", "n2_prompt_engineering", "n3_context_managment",
    "n4_creating_tools", "n5_creating_skills", "n6_agent_team",
    "use_mode", "use_frequency", "ai_code_flow_curr", "ai_code_flow_prev",
    "gigacode_ca", "ag_coding_course", "ai_pdlc_course", "gigacode_course"
  ],
  "filters": {
    "type": "condition",
    "column": "tn",
    "operator": "=",
    "value": "<подставь табельный номер>"
  },
  "order_by": [
    {"field": "calc_date", "kind": "column", "direction": "desc"}
  ],
  "limit": 12,
  "offset": 0
}
```

## Что подставить

- `value` в фильтре по `tn` — табельный номер сотрудника, строкой. Витрина
  адресует сотрудника только по `tn`, других идентификаторов нет.
- Резолв ФИО → `tn` выполняй через референс `lookup_employee_by_name`
  (готовый `mcp_query` по `dm_core.employee_actual` из системного промпта)
  перед вызовом запроса.

## Обогащение вывода (ФИО, должность, блок)

Витрина даёт только `tn`. ФИО, должность и блок бери из `employee_actual`
готовым запросом резолва (тот же, что в системном промпте), подставив
`employee_id` в фильтр:

```json
{
  "schema": "dm_core",
  "logic_model": "employee_actual",
  "columns": ["person_id", "employee_id", "employee_full_name", "position_name", "fblock_name"],
  "filters": {
    "type": "and",
    "conditions": [
      {"type": "condition", "column": "employee_status", "operator": "=", "value": "активный"},
      {"type": "condition", "column": "employee_id", "operator": "=", "value": "<tn>"}
    ]
  },
  "limit": 5,
  "offset": 0
}
```

Фильтр `employee_status = активный` НЕ убирай — иначе по одному табельному
номеру подтянутся и уволенные строки, и в ответ попадут чужие ФИО,
должность и блок.

Не упоминай пользователю название запроса и сам факт обращения к
`employee_actual` — просто показывай ФИО, должность, блок и табельный
номер вместе с навыками.

## На что обратить внимание

- На один табельный номер бывает несколько строк (по одной на дату
  расчёта). `order_by calc_date desc` плюс небольшой `limit` дают последний
  срез сверху — для ответа бери первую строку.
- `n1..n6` — уровни навыков (Int32). Шкала в каталоге не зафиксирована —
  не придумывай границы, приведи числа как есть и поясни, что это уровни
  поставщика.
- `ag_coding_course`, `ai_pdlc_course`, `gigacode_course` — обучение
  (Int32, признак или статус). `use_mode` — код режима, `gigacode_ca` —
  флаг строкой.
- `ai_code_flow_curr` и `ai_code_flow_prev` — доля ИИ-кода (Float64) за
  текущий и предыдущий месяцы, в диапазоне **от 0 до 1** (1 = 100%). Для
  процентов умножай значение на 100.
