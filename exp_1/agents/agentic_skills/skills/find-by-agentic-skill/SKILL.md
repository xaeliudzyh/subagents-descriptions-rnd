# Найти сотрудников по уровню агентного навыка и роли

Возвращает список сотрудников, у которых уровень выбранного агентного
навыка не ниже порога, с отбором по основной роли (по витрине
`stable.agentic_skill_level`).

## Когда использовать

- Нужно найти людей с определённым уровнем навыка: «найди сотрудников с
  prompt engineering от 2», «кто владеет созданием скиллов на уровне 3».
- Поиск с уточнением по роли: «разработчики с уровнем агентного навыка
  не ниже 2».
- Собрать список с табельными номерами, уровнем навыка и долей ИИ-кода.

## Параметры запроса

| Параметр | Допустимые значения | Куда подставляется |
|----------|---------------------|--------------------|
| `skill_min` | один из: `n1_prompting`, `n2_prompt_engineering`, `n3_context_managment`, `n4_creating_tools`, `n5_creating_skills`, `n6_agent_team` | имя колонки в узле `condition` (порог `>=`) |
| `role` | основная роль (точное значение, свободный текст) | `value` в узле `condition` по `role_main` |

## Алгоритм

1. **Определи навык и порог.** Выбери ОДИН навык `skill_min` из шести и
   порог уровня (`>=`). Если пользователь назвал несколько навыков —
   уточни, по какому искать (ищем по одному навыку за раз).
2. **Определи роль** (если задана). Порог по роли — точное значение
   `role_main`. Роль — свободный текст: если точное значение не подходит
   или пользователь называет её частично — используй поиск по подстроке
   (`condition_like`, `ILIKE`).
3. **Выполни готовый запрос** через `mcp_query`, подставив `skill_min` в
   имя колонки фильтра по навыку, порог — в `value` этого узла, роль — в
   `value` узла по `role_main`. Не меняй структуру дерева фильтров и набор
   полей.
4. **Обогати список.** Получи ФИО, должность (`position_name`) и блок
   (`fblock_name`) для всех `tn` из результата витрины — запросом по
   `employee_actual` с фильтром `employee_id` через `condition_in` (готовый
   запрос резолва из системного промпта, добавь узел `condition_in` со
   списком `tn` рядом с фильтром по `employee_status`; листай `offset`, пока
   не соберёшь всех).
5. **Собери ответ**: по каждому сотруднику — ФИО, должность, блок,
   табельный номер `tn`, уровень выбранного навыка и долю ИИ-кода.

## ГОТОВЫЙ ЗАПРОС

```json
{
  "schema": "stable",
  "logic_model": "agentic_skill_level",
  "columns": [
    "tn", "calc_date", "role_main", "expertise_area",
    "n1_prompting", "n2_prompt_engineering", "n3_context_managment",
    "n4_creating_tools", "n5_creating_skills", "n6_agent_team",
    "ai_code_flow_curr"
  ],
  "filters": {
    "type": "and",
    "conditions": [
      {"type": "condition", "column": "<навык skill_min>", "operator": ">=", "value": <порог>},
      {"type": "condition", "column": "role_main", "operator": "=", "value": "<роль>"}
    ]
  },
  "order_by": [
    {"field": "calc_date", "kind": "column", "direction": "desc"},
    {"field": "<навык skill_min>", "kind": "column", "direction": "desc"}
  ],
  "limit": 50,
  "offset": 0
}
```

## Что подставить

- `column` в узле фильтра по навыку (и в `order_by`) — имя выбранного
  навыка `skill_min` (например `n2_prompt_engineering`).
- `value` этого узла — порог уровня.
- `value` узла по `role_main` — основная роль (строка).
- Если роль не задана — этот узел условия не включай (оставь только фильтр
  по навыку), не придумывай роль.

## Обогащение вывода (список: ФИО, должность, блок)

Витрина даёт только `tn` у людей в списке. ФИО, должность и блок всех них
бери из `employee_actual` запросом резолва (из системного промпта), добавив
узел `condition_in` по `employee_id`:

```json
{
  "schema": "dm_core",
  "logic_model": "employee_actual",
  "columns": ["person_id", "employee_id", "employee_full_name", "position_name", "fblock_name"],
  "filters": {
    "type": "and",
    "conditions": [
      {"type": "condition", "column": "employee_status", "operator": "=", "value": "активный"},
      {"type": "condition_in", "column": "employee_id", "operator": "IN", "value": ["<tn1>", "<tn2>", "..."]}
    ]
  },
  "limit": 100,
  "offset": 0
}
```

Фильтр `employee_status = активный` НЕ убирай — иначе по одному табельному
номеру подтянутся и уволенные строки, и в списке окажутся чужие ФИО,
должность и блок.

Листай `offset`, пока не соберёшь всех сотрудников из результата витрины.
Не упоминай пользователю название запроса и сам факт обращения к
`employee_actual` — показывай ФИО, должность, блок и табельный номер по
каждому сотруднику.

## На что обратить внимание

- Порог применяется к ОДНОМУ выбранному навыку. Меняй имя колонки на
  нужный навык и порог под задачу.
- `n1..n6` — уровни навыков (Int32). Шкала в каталоге не зафиксирована —
  трактуй по данным, не придумывай границы.
- Один табельный номер может встретиться несколько раз (по дате расчёта).
  Для последнего среза добавь отбор по `calc_date` или листай с учётом дат.
- `ai_code_flow_curr` — доля ИИ-кода (Float64) за текущий месяц, в диапазоне
  **от 0 до 1** (1 = 100%). Для процентов умножай значение на 100.
- Роль — свободный текст; при несовпадении точного значения используй
  поиск по подстроке (`condition_like`, `ILIKE`).
