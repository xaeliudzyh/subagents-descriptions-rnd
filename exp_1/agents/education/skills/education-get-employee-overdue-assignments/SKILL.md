# Инструкция: просроченное обучение сотрудника

> ⚠️ **Формат `mcp_query`:** `columns`/`order_by`/`metrics` — массивы `[...]`, `filters` — объект `{...}`, `limit` — число (без кавычек). НЕ передавай их строками (`"[...]"`, `"100"`). См. AGENTS.md «КАК ПРАВИЛЬНО ВЫПОЛНЯТЬ ЗАПРОСЫ».

## Когда использовать

Вопросы «какие курсы просрочил / что горит у **одного** сотрудника» (по
`person_id`), «предстоящие дедлайны ближайших N дней». Перечень по команде или
счёт — скиллы `education-get-subordinates-overdue-assignments` /
`education-get-overdue-summary`.

## Модель

- **Модель:** `dm_core.employee_education` (одна строка = одно назначение).
- Фильтр по `person_id = X` уже сужает данные до одного человека, поэтому
  `person_id` и `employee_full_name` в `columns` не нужны — оставь только курсы.

---

## Параметры

| Параметр | Обязательный | Описание |
|---|---|---|
| `person_id` | да | UUID сотрудника → `value` фильтра `person_id` |
| `current_date` | да | Текущая дата `YYYY-MM-DD` |
| `horizon_date` | нет | Верхняя граница окна (для «предстоящие») |
| `mode` | нет | Что показывать: `overdue` / `upcoming` / `both` (по умолчанию `both`) |
| `horizon_days` | нет | Кол-во дней для «предстоящие» (по умолчанию 10) → `horizon_date` |

Меняй только значения. Структуру шаблона, колонки и операторы не меняй.

---

## Обязательное уточнение: группа людей

Этот скилл работает по **одному конкретному сотруднику**. Перед запросом ВСЕГДА
убедись, что определена группа — конкретный человек (`person_id`):

- Если `person_id` уже известен из вопроса — подтверди его и начинай.
- Если известен только ФИО — получи `person_id` (lookup по сотруднику) и
  уточни у пользователя, того ли человека он имел в виду, если есть неоднозначность.
- Если вопрос про команду или курс — это НЕ сюда: используй
  `get-subordinates-overdue-assignments` / `find-overdue-by-course` /
  `get-overdue-summary`.

Не выполняй запрос, пока не определён конкретный человек.

## Уточнение среза (короткое)

После определения человека уточни, что показать (предлагай дефолт):

1. **Что отобразить?** «Просроченные, предстоящие или оба?»
   - `overdue` — только базовый шаблон (просроченные);
   - `upcoming` — только окно предстоящих;
   - `both` (дефолт) — оба среза.
2. **На сколько дней вперёд?** (для предстоящих). Дефолт — 10 дней.
   «Предстоящие» — окно `[current_date, horizon_date]`.

**Не спрашивай**, если ответ очевиден: «что горит/просрочил» — `overdue`;
«скоро дедлайн / предстоящие» — `upcoming`; иначе — `both`.

## Шаблон (базовый — «просроченные назначения»)

```json
{
  "schema": "dm_core",
  "logic_model": "employee_education",
  "columns": ["item_name", "playlist_name", "item_deadline_dt"],
  "filters": {
    "type": "and",
    "conditions": [
      { "type": "condition", "column": "person_id", "operator": "=", "value": "<PERSON_ID>" },
      { "type": "condition", "column": "assignment_status", "operator": "=", "value": "ACTIVE" },
      { "type": "condition", "column": "item_deadline_dt", "operator": "<", "value": "<CURRENT_DATE>" }
    ]
  },
  "order_by": [
    { "field": "item_deadline_dt", "kind": "column", "direction": "asc" }
  ],
  "limit": 10
}
```

## Вариант «Предстоящие дедлайны в ближайшие N дней»

Тот же запрос, но дедлайн в окне `>= <CURRENT_DATE>` и `<= <HORIZON_DATE>`
(верхняя граница = `current_date + horizon_days`): замени фильтр
`item_deadline_dt` на два условия `>=` и `<=`. Подставь `<PERSON_ID>`,
`<CURRENT_DATE>`, `<HORIZON_DATE>` в `value`.

## Вариант «Оба среза»

Если выбран `both` — выполни базовый шаблон (просроченные) и вариант предстоящих
порознь, затем сведи в ответ. Для каждого среза `limit ≤ 10`.

## Как читать результат

| Поле | Что вернуть |
|---|---|
| `item_name` | Название курса |
| `playlist_name` | Плейлист |
| `item_deadline_dt` | Дедлайн |

- Сортировка по дедлайну по возрастанию. Для предстоящих — «дедлайн ещё не наступил».
- Просрочка считается только по заполненному дедлайну; без него строки не попадают.
- Пустой ответ = просроченных назначений нет (не ошибка).
- **Минимальные чанки:** `limit ≤ 20`. «Сколько» у сотрудника — скилл
  `education-get-overdue-summary`. Не пересказывай сырой ответ инструмента.
