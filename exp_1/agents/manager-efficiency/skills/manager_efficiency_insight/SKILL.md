# Вход и ответственность

ФИО, выбранная структура, четыре квартала Q1→Q4 в хронологическом порядке, матрица metric×quarter,
статусы качества, фактические даты и доступные сведения о заполнении previous.
Данные бери только из get_efficiency_metrics. Самостоятельно запросы не повторяй.
Q1 и Q4 здесь означают первый и последний кварталы горизонта, а не номера кварталов года.

# Ограничение ответа одной структурой

По умолчанию выводи только ОШС; Agile — отдельным ответом по просьбе пользователя.
Применяй реестр ниже только к трём метрикам выбранной структуры и общему признаку
наставника/коуча. Показатели другой структуры не включай даже в список пропусков.
После двух блоков ответа по ОШС отдельной строкой спроси:
«Сформировать отдельный инсайт по Agile для этого же руководителя и периода?»
После ответа по Agile этот вопрос не добавляй. Признак наставника/коуча всегда общий.

# Реестр норм

Цели заданы для интерпретации. Они не являются параметрами MCP или формулами метрик.
target_value: null означает «Норма не задана», а не ноль. Не придумывай норму.
Для наставника/коуча целевое значение — 1, значение 0 не соответствует цели.

```json
{
  "one_to_one_coverage_pct_oshs": {
    "target_value": null,
    "comparison": null,
    "direction": "higher_is_better",
    "unit": "percent"
  },
  "one_to_one_coverage_pct_agile": {
    "target_value": null,
    "comparison": null,
    "direction": "higher_is_better",
    "unit": "percent"
  },
  "manager_assigned_learning_pct_oshs": {
    "target_value": null,
    "comparison": null,
    "direction": "higher_is_better",
    "unit": "percent"
  },
  "experienced_employees_oshs": {
    "target_value": null,
    "comparison": null,
    "direction": "context_required",
    "unit": "percent"
  },
  "manager_assigned_learning_pct_agile": {
    "target_value": null,
    "comparison": null,
    "direction": "higher_is_better",
    "unit": "percent"
  },
  "experienced_employees_agile": {
    "target_value": null,
    "comparison": null,
    "direction": "context_required",
    "unit": "percent"
  },
  "is_mentor_or_coach": {
    "target_value": 1,
    "comparison": "equals",
    "direction": "higher_is_better",
    "unit": "boolean"
  }
}
```

direction = higher_is_better позволяет оценить рост как улучшение показателя,
снижение как ухудшение. Для context_required показывай изменение нейтрально:
доля опытных сотрудников сама по себе не доказывает улучшение команды.
При выводе по динамике без числовой цели кратко поясни, что цель не задана. Не выводи это пояснение для исключённых из ответа показателей.
Не придумывай пороги для встреч, обучения или стажа. Не используй средние по другим
руководителям вместо заданных целей. Изменять цели можно только по явной постановке владельца методики.

# Расчёт и поиск закономерностей

Для каждой процентной метрики вычисли Q2−Q1, Q3−Q2, Q4−Q3 и Q4−Q1,
только если обе точки соответствующей пары валидны. Разности — процентные пункты.
Вычисляй до округления, показывай до двух десятичных знаков. Не усредняй структуры.
При четырёх валидных точках:
- все три изменения > 0: рост каждый квартал;
- все три < 0: снижение каждый квартал;
- все три = 0: без изменений;
- изменения >= 0 с хотя бы одним ростом: рост с периодами стабильности;
- изменения <= 0 с хотя бы одним снижением: снижение с периодами стабильности;
- есть и рост, и снижение: колебания; опиши направление последнего перехода.
При пропусках не утверждай непрерывный тренд. Разность Q4−Q1 при пустых Q2/Q3
можно показать только как изменение между двумя датами, явно указав пропуски.
Не подменяй отсутствующий Q4 более ранней точкой. Сравнение чисел не доказывает причинность.
Если источник применяет previous и не раскрывает происхождение значений, не называй
четыре точки четырьмя независимыми наблюдениями.

# Отбор выводов в два блока

Используй заголовки «Точки роста» и «Сильные стороны».
Текущий уровень и направление изменения — отдельные оценки.

«Точки роста»:
- в последнем квартале признак наставничества равен 0 при цели 1;
- значение показателя с direction=higher_is_better снизилось к предыдущему
  кварталу или первому кварталу горизонта; укажи точно, за какой период;
- рост ещё не довёл показатель до цели: признай рост, но покажи оставшееся отставание.
Стабильное отставание от цели называй отставанием без ухудшения. Не делай вывод
«всё плохо» о человеке. Если норматив не задан, не объявляй значение плохим
только потому, что это 0 или оно кажется небольшим.

«Сильные стороны»:
- цель превышена или достигнута, и нет выявленного ухудшения за сравниваемые периоды;
- появился или сохраняется признак наставника/коуча 1;
- показатель higher_is_better растёт и нет установленного отставания от цели.
  Если числовой цели нет, говори о положительной динамике, а не о соответствии норме.

Если показатель выше цели, но снизился — помести его в «Точки роста»,
добавив, что он остаётся выше цели. Не дублируй тот же показатель во втором блоке.
Если за горизонт рост, но последний квартал хуже, покажи оба изменения в одном
выводе первого блока. При иной разнонаправленной динамике также не скрывай снижение.
Контекстные показатели стажа не относить к хорошему/плохому автоматически.
Стабильные показатели без цели не заполняют ни один блок ради объёма.

Для каждого вывода используй реальные даты и значения. Пиши разности процентов
в процентных пунктах. Для наставничества используй переход 0→1 или 1→0.
При отсутствующем последнем квартале не объявляй прежнее значение текущим.
Не придумывай причины изменений и действия, которых нет в утверждённой методике.

# Предметный смысл

Встречи: рост охвата встречами 1:1, не доказательство качества встреч.
Обучение: рост охвата назначениями, не прохождение курсов и не рост компетенций.
Опыт: изменение состава команды, без выдуманных причин найма или увольнения.
Наставник/коуч: 0→1 — появился признак и достигнута цель; 1→0 — признак перестал
фиксироваться, цель не достигнута; 1→1 — цель сохранена; 0→0 — цель не достигнута,
без ухудшения. Не рассчитывай процентные пункты для этого признака. Не делай выводов
о фактическом прекращении наставничества только по бейджу. Показывай цель 1 (Да).

# Пропуски и ошибки

NULL сохраняй в рабочей матрице как отсутствие данных. Ноль — значение.
Полную матрицу и список пропусков оставляй для диагностики, не для пользовательской таблицы.
Отличай NULL/пустую выдачу, ошибку запроса и невалидное значение. Причину отсутствия
данных не угадывай. Проценты вне 0–100 и признак вне {0,1} исключай из интерпретации.
Для такой ячейки выводи «Некорректное значение» и сохраняй диагностическое пояснение.
Если нет оснований для одного из блоков динамики, напиши «Не выявлены по доступным данным».
Если все процентные значения пусты, прямо скажи, что процентную динамику оценить
невозможно; отдельно можно описать валидный признак наставничества.

# Формат ответа: два связных текста

Образец оформления — короткие содержательные абзацы, а не отчёт о расчётах.
Одна вводная строка: ФИО, выбранная структура и период, например «IV квартал 2025 — III квартал 2026».
Далее ровно два блока в указанном порядке:

**Сильные стороны**
Один связный абзац, объединяющий до трёх наиболее значимых подтверждённых сигналов.
Начни с конкретного вывода, затем подкрепи цифрами и динамикой.

**Точки роста**
Один связный абзац, объединяющий до трёх наиболее значимых подтверждённых отклонений.
Начни с того, что требует внимания, затем укажи текущий уровень, цель и динамику.

Это названия двух блоков, не оценка личности. Внутри не делай списков, таблиц,
подзаголовков по каждой метрике или отдельных разделов по структурам.
Все структурные показатели в ответе относятся только к выбранной структуре. Не смешивай ОШС и Agile.
Наставничество — общий признак руководителя, не приписывай его отдельной структуре.
Обычно достаточно 2–5 предложений на блок. Не заполняй объём неподтверждёнными сигналами.

Для выбранного сигнала включи последнее значение, сравнение с предыдущим и первым
кварталом при наличии точек, а также известную цель. Если все четыре значения равны,
достаточно «сохраняется на уровне X все четыре квартала» вместо перечисления дат
и трёх нулевых разностей. В остальных случаях называй периоды сравнения.
Отбор: сначала отклонение от известной цели, затем ухудшение последнего квартала,
затем изменение за весь горизонт; для сильных сторон — сохранённая цель и рост.
Не сравнивай величину процентного отклонения с бинарным признаком как единый рейтинг.
Если другие значимые сигналы не вошли из-за лимита, не заявляй, что перечислено всё.

Не переноси из примеров чужие цифры, нормы, веса, показатели результативности,
вовлечённости, текучести и кросс-целей. Они отсутствуют в наших запросах.
Количество назначений обучения и количество встреч — не процент охвата.
Нельзя переносить на наш процент порог «хотя бы одно назначение/одна встреча».
Стабильный ноль без заданной нормы не даёт оснований ни для похвалы, ни для точки роста.
Нулевые значения не исключай из расчётов как пропуски.
Не придумывай сильную сторону, если её нет. Не используй запасные утверждения
«ровный профиль», «устойчивая команда», «всё в норме» только ради второго абзаца.

Допустим короткий следующий шаг непосредственно по выявленному отклонению:
«Стоит проверить…» или «Обратите внимание на…». Это предложение для обсуждения,
не установленная причина и не обещание эффекта. Не выдумывай план действий,
численность, причины ухода, качество управления или кадровые решения.

При отсутствии оснований:
- Сильные стороны: «По доступным показателям пока недостаточно оснований выделить сильные стороны».
- Точки роста: «По доступным показателям отклонений от заданных целей и отрицательной динамики не выявлено».
Вторая формулировка не означает, что все показатели соответствуют нормам.
Если пропуски ограничивают выводы, добавь в конце второго абзаца одно предложение
с понятным названием недоступного направления, без NULL и технических имён полей.
При отсутствии всех данных сообщи, что оценить сильные стороны и точки роста невозможно.

# Проверка готового ответа перед отправкой

1. Для каждого предложения есть основание в полученных данных и реестре норм.
2. Стабильные нули без нормы и нейтральные изменения стажа не представлены как недостатки.
3. Каждый сигнал относится только к одному блоку; названия показателей сохраняют исходный смысл.
4. Сохранены направления изменений, границы целей и единицы измерения.
5. Ответ содержит вводную строку и два связных абзаца под двумя заголовками; после ОШС — вопрос о разборе Agile.
6. Удалены таблицы, JSON, технические названия, UUID, протокол шагов и фразы
   «данные получены», «теперь формирую инсайт», «сравнил кварталы».

До финального ответа используй инструменты, но не печатай промежуточные матрицы
и расчёты как сообщения пользователю. Рабочие данные остаются в результатах
инструментов и доступном контексте выполнения. Не утверждай, что самостоятельно
записал лог. Способ журналирования определяется приложением, а не этим скиллом.
Текстовые инструкции не заменяют программную проверку фактического ответа.
Не создавай общий балл, рейтинг, прогноз, оценку личности или кадровую рекомендацию.
