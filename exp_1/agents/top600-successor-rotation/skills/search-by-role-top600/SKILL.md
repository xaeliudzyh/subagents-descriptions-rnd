# Поиск кандидатов под роль (search-by-role-top600)

Скилл вызывается, когда пользователь называет должность, а не человека: «подбери мне кандидатов под роль директор HR». Слово «мне» указывает, кому нужен результат, а не на чьё место подбирать.

## Алгоритм работы

1. **Название роли.** Извлеки из запроса название должности вместе с направлением и специализацией («директор HR», «CDS в HR»), без слов-обращений. Если названия нет — уточни его у пользователя. Передай название в `find_top600_roles(role_query)`.
2. **Выбор роли.** Из массива `roles` выбери одно название, которое по смыслу лучше всего соответствует запросу. Учитывай функцию, специализацию и уровень ответственности (по названию и обязанностям роли), допускай опечатки и общеупотребительные сокращения. Близость только помогает упорядочить варианты и сама по себе совпадение не подтверждает.
   - Массив пуст или ни одна роль не подходит — ответь «Не нашёл подходящей роли среди ТОП-600. Как ещё можно назвать эту должность?» и дождись ответа. Новое название снова передай в `find_top600_roles`.
   - Тул вернул `message` — сообщи пользователю, что поиск ролей сейчас недоступен, и заверши работу по скиллу.
3. **Подбор.** Вызови `get_role_candidates(role_employee_id)` с `role_employee_id` выбранной строки из ответа `find_top600_roles`. Это служебный идентификатор роли: не подставляй вместо него ТН пользователя или кандидатов и не показывай его пользователю.
   - Тул вернул `message` — сообщи пользователю, что подбор сейчас недоступен, и заверши работу по скиллу.
   - Список `candidates` пуст — сообщи, что для этой роли рекомендаций нет, и заверши работу по скиллу.
4. **Оценка.** Прочитай `candidate-list-common-successor-rotating-top600`. Веса компетенций определи по описанию роли (`position.position_text`), уровни текстового совпадения — по описанию роли и профилю каждого кандидата (`candidate_text`). При неполном описании опирайся только на доступные сведения. Вызови `score_role_candidates` с тем же `role_employee_id`, весами и уровнями. Результаты сопоставляй с профилями по ТН кандидата.
   - Все кандидаты исключены по баллу — сообщи, что для этой роли рекомендаций нет, и заверши работу по скиллу.
   - При ошибке оценки не выдавай предварительный список за результат.
5. **Ответ.** Прочитай `candidate-analyze-successor-rotating-top600` и `answer-widget-top600`. Во всём ответе называй роль так, как её назвал пользователь (с исправлением явных опечаток), а не названием, выбранным из ответа `find_top600_roles`: подобранное название — служебное, пользователю его не показывай. Оформи один виджет «Кандидаты на роль „<роль из запроса пользователя>“» и детальные оценки по убыванию итогового балла, одним разделом. В обоснованиях опирайся на обязанности, функции и навыки роли и на факты из профиля каждого кандидата.
6. На этом работа по скиллу завершена — дальнейших действий не предлагаем.

## Ограничения

- В этом сценарии нет конкретного сотрудника, на чьё место подбирают кандидатов: не упоминай его, его подразделение, грейд и текущих преемников.
- Все кандидаты оцениваются одинаково, в том числе те, кто уже работает в такой должности: отдельно их не выделяй и не комментируй.
