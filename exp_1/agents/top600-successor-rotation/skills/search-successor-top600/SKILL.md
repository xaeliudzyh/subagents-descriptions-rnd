# Поиск и подбор преемников (search-successor-top600)

Скилл вызывается, когда пользователь запрашивает **формирование преемников на персону** (ФИО, табельный номер или person_id).

Если пользователь назвал только должность («кандидаты на роль директора HR»), перейди к `search-by-role-top600`.

## Входные данные

От пользователя ожидается ТН и/или ФИО и/или person_id(id профиля) того, кому подбирать преемников, **или ничего из этого**, если он подбирает преемников для себя.

## Алгоритм работы

1. Определяем ТН человека, на кого искать преемников, тулом `resolve_top600_employee`:
   - назван ТН — передаём `employee_id`; в задании передан id профиля (person_id) целевого сотрудника — `person_id`;
     названо ФИО — `full_name`; названа позиция — `position_id`;
   - передан `person_id` — ФИО и ТН у пользователя не спрашиваем;
   - пользователь подбирает преемников **себе** («мне», «на моё место») — вызываем тул **без аргументов**;
     если в задании передан `person_id` другого сотрудника, а пользователь о себе не говорит, — без аргументов не вызываем, передаём `person_id`;
   - вернулся `matches` — показываем список пользователю и уточняем, кого он имел в виду;
   - вернулось `message` без `matches` при поиске по уменьшительному / разговорному имени («Аня», «Саша») — один раз повторяем вызов с полным именем («Анна», «Александр» / «Александра»), фамилию оставляем как есть;
   - вернулось `message` без `matches` (в том числе после повтора с полным именем) — персоны нет среди сотрудников ТОП-600: объясняем это пользователю и завершаем работу по скиллу.
2. Вызываем тул `get_successor_candidates` для определения списка преемников по `employee_id`:
   - Тул возвращает `{"position": ..., "candidates": [...], "successors": [...]}` либо `{"message": "<неуспех>"}`.
   - Если вернулась ошибка/`message` — верни пользователю понятное объяснение и заверши работу по скиллу.
3. Полученный список `candidates` оцениваем по логике, описанной в скилле `candidate-list-common-successor-rotating-top600`.
4. Формируем детальную оценку соответствия по структуре и методологии, описанной в скилле `candidate-analyze-successor-rotating-top600`.
5. Формируем и возвращаем результат пользователю. **ОБЯЗАТЕЛЬНО сохрани заданную структуру ответа (не добавляй новых блоков и не убирай имеющиеся):**
   1. Информация о позиции: одной строкой строго в формате «Позиция: <название должности>»
      (название — первая строка `position_text`; грейд и id позиции не выводим, имена полей тоже).
      Пример: «Позиция: Директор ДИТ».
   2. Текущие преемники на позиции (на основе поля `successors`): ФИО через запятую — они должны быть **кликабельными**: `[full_name](https://hr.sberbank.ru/platform/profile/<person_id>)`.
   3. Список кандидатов (от лучшего балла к худшему). Колонки списка (формируем на основании `candidates`) **СТРОГО содержат следующее**:
      - **"ФИО"** — `employee_full_name` в виде ссылки на профиль: `[employee_full_name](https://hr.sberbank.ru/platform/profile/<person_id>)`;
      - **"Название должности"** — `professionlevel_name`;
      - **"Название подразделения"** — последнее название в строке `unit_names`;
      - **"Оценка соответствия"** — финальный балл `score` из ответа `score_successor_candidates` (шаг 3), по нему ранжируется список.
      Сырой `ml_score` пользователю не показываем.
   4. Пояснение к оценке соответствия — сразу под таблицей, дословно:
      > Оценка соответствия считается по шкале от 0 до 10 из трёх компонентов: соответствие кандидата требованиям позиции (вес 70%), уровень компетенций (20%), результативность (10%). Задайте вопрос, если требуется более детальная методология.
6. На этом работа по скиллу завершена — следующих шагов нет, никаких дальнейших действий не предлагаем. Ответ заканчивается финальной фразой. 

## Ссылки на смежные скиллы

- `candidate-list-common-successor-rotating-top600` — методика подсчёта финального балла.
- `candidate-analyze-successor-rotating-top600` — логика формирования анализа по кандидатам.
