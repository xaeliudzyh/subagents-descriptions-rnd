# Методика финального балла кандидатов (candidate-list-common-successor-rotating-top600)

Скилл описывает методологию проставления **финального балла каждому из кандидатов**. Является дополняющим к скиллам `search-successor-top600`, `search-by-role-top600` и `search-rotating-top600`.

> **Внутренняя методика.** Всё, что здесь описано (обозначения R, K, P, T, c_weighted, формулы) — это логика расчёта для агента и тула. В ответе пользователю эти переменные и формулы **не показываются**: пользователю выдаётся только итоговая «Оценка соответствия» и деловое обоснование (см. `candidate-analyze-successor-rotating-top600`).

## Методика

Для проставления финального балла (от 0 до 10) используется формула:

> Score = (R * 0.7 + K * 0.20 + P * 0.10) * 10, где
>   - **R** — Соответствие требованиям (в шкале 0..1);
>   - **K** = `mean_competency` — средний балл компетенций кандидата (`avg_competence_score / 100`, в шкале 0..1);
>   - **P** = `performance` — результативность кандидата (в шкале 0..1).

> Примечание: все три компонента (`R`, `K`, `P`) возвращаются в шкале 0..1.
> Финальный балл приводится к шкале 0..10 домножением формулы на 10.
> Отсечка `< 5` в шкале 0..10 соответствует исходной `< 0.5`.
> **Округление:** итоговый `Score` округляется до 1 знака после запятой.

При этом если финальный балл кандидата **менее 5 баллов**, он **исключается из финального списка**.

## Оценка соответствия требованиям (R)

**На основе чего считаем:**
- Скор от ретривела (`ml_score`);
- Целевые баллы компетенций (`wide_context_score`, `result_management_competency_score`, `centricity_competency_score`, `system_thinking_competency_score`, `cooperation_competency_score`);
- Текст позиции (`position_text`);
- Текст кандидата (`candidate_text`).

**Методология расчёта:**

> R = clamp((ml_score + (c_weighted * T)) / 2, 0, 1), где
>   - `c_weighted` — балл соответствия целевым компетенциям;
>   - `T` — коэффициент сравнения текста кандидата и позиции.

**Балл соответствия целевым компетенциям (c_weighted):**
- Считается на основе целевых баллов компетенций.
- Необходимо оценить важность компетенции исходя из текущих требований и проставить каждой из них **вес**. Вес определяется в зависимости от того, что необходимо по позиции. **Сумма весов должна равняться единице.**

Правила изменения весов:

| Компетенция | Критерии повышения веса важности (по позиции важно) |
|-------------|-----------------------------------------------------|
| `wide_context_score` (Широта и системность) | "системное/стратегическое мышление", "учёт внешнего контекста", "стратегическое видение", "работа на стыке направлений" |
| `result_management_competency_score` (Управление результатом) | "нацеленность на результат", "KPI", "ответственность за сроки", "амбициозные цели" |
| `centricity_competency_score` (Клиентоцентричность) | "клиентоориентированность", "работа с клиентом", "пользовательский опыт", "продукт для клиента" |
| `system_thinking_competency_score` (Системное мышление) | "генерация идей", "стратегия", "архитектура", "комплексные решения" |
| `cooperation_competency_score` (Кооперация / Сотрудничество) | "сотрудничество", "командная работа", "взаимодействие подразделений", "работа в кросс-функциональных командах" |

- Пропуски в скорах компетенций заполняются **средним баллом по этой компетенции у всех кандидатов**.
  Также заполняются пропуски в `mean_competency` (K) и `performance` (P).
- Формула:
    > c_weighted = sum(w_i * c_i) / 10, где
    >   - `w_i` — веса, выведенные из текста (сумма == 1);
    >   - `c_i` — баллы компетенций кандидата (0-10).

**Сравнение кандидата и позиции (T):**
- Экспертно оцениваем смысловые пересечения позиции `position_text` и профиля кандидата `candidate_text`.
- На основе пересечений определяем **уровень** текстового совпадения (0–3); в тул передаётся уровень, коэффициент T по нему подставляет тул:

| Уровень текстового совпадения | Описание | T (коэффициент) |
|-------------------------------|----------|-----------------|
| 0 (Нет совпадений) | В опыте нет ни одной ключевой технологии/задачи из требований | 0.95 (лёгкий штраф) |
| 1 (Частичное) | Есть 1-2 пересечения, но они не являются ядром позиции | 1.00 (нейтрально) |
| 2 (Сильное) | Есть 2-3 прямых пересечения по ключевым задачам позиции | 1.05 (ощутимый) |
| 3 (Идеальное) | Опыт кандидата текстуально дублирует 80%+ ядра требований | 1.10 (макс.) |

## Порядок действий при применении

Экспертную часть методики (веса и уровни T) определяешь ты, расчёт по формулам выполняет тул
`score_successor_candidates` (трек «Преемники»), `score_role_candidates` (поиск под роль) или `score_rotation_candidates` (трек «Ротации»).

1. По тексту позиции `position_text` определяем веса пяти целевых компетенций (сумма == 1).
2. Для **каждого** кандидата сравниваем `position_text` и `candidate_text` и определяем уровень текстового совпадения (0–3) с кратким обоснованием.
3. Вызываем тул трека с теми же аргументами цели, что и тул подбора кандидатов, и передаём:
   - `competency_weights` — `{"wide_context_score": ..., "result_management_competency_score": ..., "centricity_competency_score": ..., "system_thinking_competency_score": ..., "cooperation_competency_score": ...}`;
   - `text_match` — `[{"employee_id": "<ТН>", "level": <0..3>, "reason": "<обоснование>"}]` по всем кандидатам подбора.
4. Тул заполняет пропуски средними, считает `c_weighted`, `R`, `K`, `P` и финальный `score` (0..10) и возвращает кандидатов по убыванию балла.
   Если тул вернул `message` о некорректных параметрах — исправь веса или уровни и вызови его повторно.
5. Кандидатов с `excluded: true` (`score < 5`) исключаем; порядок остальных берём из ответа тула.

> Примечание: `R`, `K`, `P` подставляются в формулу в шкале 0..1; в шкалу 0..10 приводится только итоговый `Score` (домножением на 10).
