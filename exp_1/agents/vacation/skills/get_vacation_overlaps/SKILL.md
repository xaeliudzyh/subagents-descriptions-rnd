# Пересечения отпусков подчиненных

Показывает, кто из подчиненных руководителя уходит в отпуск одновременно,
за запрошенный период. Промежуточные запросы и расчеты пользователю не выводи.

## Алгоритм

1. **Определи период.**
   - Один запрос = один календарный год.
   - Период указан (месяц/диапазон одного года) — используй его как есть.
   - Период пересекает границу года или несколько лет — попроси выбрать один год, запрос не выполняй.
   - Период не указан — бери будущее: от текущей даты до 31 декабря текущего года.
   - Неоднозначный период — уточни до выполнения.

2. **Получи подчиненных** запросом к `dm_core.employee_actual` (узлы
   `condition_array` + `has`). Для каждого подчиненного сохрани
   `employee_id`, `person_id`, ФИО.

   Готовый запрос (подставь `<PERSON_ID>` — person_id руководителя, UUID строкой, одинаковый во все 4 узла):

   ```json
   {
     "schema": "dm_core",
     "logic_model": "employee_actual",
     "columns": ["person_id", "employee_id", "employee_full_name"],
     "filters": {
       "type": "and",
       "conditions": [
         {"type": "condition", "column": "employee_status", "operator": "=", "value": "активный"},
         {
           "type": "or",
           "conditions": [
             {"type": "condition_array", "column": "agile_curator_hierarchy_person_id_main", "operator": "has", "value": "<PERSON_ID>"},
             {"type": "condition_array", "column": "agile_director_hierarchy_person_id_main", "operator": "has", "value": "<PERSON_ID>"},
             {"type": "condition_array", "column": "oshs_curator_hierarchy_person_id_main", "operator": "has", "value": "<PERSON_ID>"},
             {"type": "condition_array", "column": "oshs_director_hierarchy_person_id_main", "operator": "has", "value": "<PERSON_ID>"}
           ]
         }
       ]
     },
     "limit": 1000
   }
   ```

   - Пустой список → ответь только: `У Вас нет подчиненных сотрудников для проверки пересечений отпусков.` Запросы дальше не выполняй.
   - Техническая ошибка → `Не удалось получить информацию о подчиненных.`
   - Руководитель должен участвовать в расчете: если его нет в списке
     иерархии, получи его `employee_id`/ФИО по `person_id` и добавь.

3. **Собери список для расчета** — вся команда, минимум два разных
   `employee_id`. Не вызывай расчет с одним сотрудником.

4. **Обработай ФИО из вопроса** — резолви его скиллом
   `lookup_employee_by_name` и сверь, что названные — подчиненные.
   Неподчиненного не включай; ответь:
   `Я могу показать пересечения отпусков только среди ваших подчиненных сотрудников.`

5. **Получи пересечения** скиллом `find_vacation_overlaps` (заново при каждом
   вызове, не бери из контекста). Передай список `employee_id` и период.

6. **Разверни `overlap_business` в ответ** (см. шаблон ниже). Тип отпуска
   по `absence_code`: 101/102 — отпуск; 103–113, 128–131, 139 —
   неоплачиваемый; 114–119, 140 — доп. выходной; 120/121 — учебный;
   9900/9901 — планируемый. Пересечение ограничь границами периода:
   `max(overlap_start, начало)` — `min(overlap_end, конец)`. Смежные и
   пересекающиеся интервалы одной пары объедини. Группируй по месяцу
   начала пересечения, месяцы без пересечений не выводи.

## Шаблон ответа (обязательный)

Если пересечений нет — ответь только:
`Пересечений в указанный период не найдено среди сотрудников от 13-го грейда включительно.`

При наличии пересечений — строго такой Markdown (заголовок уровня `##`,
месяц уровнем `###`, у каждого участника пункт списка, затем
`**Пересечение:**`):

```markdown
## В 2 месяцах найдены пересечения

Показаны пересечения отпусков с 01.03.2026 по 30.04.2026 среди Ваших подчиненных от 13-го грейда включительно.
---

### Март

- [Захарова Светлана Артёмовна](#): 10.03.2026–13.03.2026 (Отпуск)
- [Алексеев Александр Олегович](#): 10.03.2026–11.03.2026 (Отпуск)

**Пересечение:** 10.03.2026–11.03.2026

---

### Апрель

- [Кузнецов Иван Михайлович](#): 16.04.2026–30.04.2026 (Отпуск)
- [Захарова Светлана Артёмовна](#): 24.04.2026 (Отпуск)

**Пересечение:** 24.04.2026
```

## Граничные случаи

| Ситуация | Действие |
|---|---|
| Период не указан | Будущее: текущая дата — 31 декабря текущего года |
| Период пересекает год | Попросить один год, запрос не выполнять |
| Нет подчиненных | `У Вас нет подчиненных сотрудников для проверки пересечений отпусков.` |
| Один участник | Ответить «Пересечений не найдено…», расчет не выполнять |
| Модель вернула ошибку | `Не удалось получить данные. Вы можете посмотреть их в сервисе [Моя команда (вкладка календарь)](https://hr.sberbank.ru/platform/myteam/calendar).` |

Даты в формате `ДД.ММ.ГГГГ`. Табельные номера и `person_id` в финальный
ответ не выводи. Не выдумывай сотрудников и отпуска — если данных нет,
сообщи, что получить не удалось, и предложи сервис «Моя команда».
