# Инструкция для агента: детальные данные по сотрудникам за штатом

## Когда использовать

Если необходимо получить детальные строки по сотрудникам, которые:

- находятся за штатом (на упразднённой штатной должности);
- являются потенциальными заштатниками (ещё не достигли порога 90 дней);
- скоро окажутся за штатом (до упразднения должности не более 15 дней).

Выборка выделяет группы сотрудников за штатом с действующими льготами
(декрет; женщины, имеющие детей до 3 лет; многодетный; одинокий родитель),
декретников за штатом и внешних совместителей за штатом.

Используй скилл для анализа и ответов на вопросы о сроках, льготах, форме
работы, трудовых договорах. Для сводных метрик используй скилл
`get_outstaff_summary`.

---

## Используемый инструмент

- **MCP-сессия:** `heimdall`
- **Инструмент:** `mcp_query`
- **Модель данных:** схема `dm_core`, логическая модель `employee_actual`,
  таблица `dm_core.staff_employee_digital_profile_actual_dm`

---

## Предварительные условия

- Если нужен список подчиненных руководителя — сначала получи список
  `person_id` через скилл `get_employee_team`.
- Если нужна детализация по конкретному сотруднику — найди его по ФИО через
  скилл `lookup_employee_by_name`.
- Базовый профиль сотрудника получают через скилл `get_employee_basic_profile`.

---

## Обязательные фильтры

| Колонка | Оператор | Значение | Зачем |
|---|---|---|---|
| `employee_status` | `=` | `активный` | Только работающие сотрудники |
| `is_outstaff_total` | `=` | `1` | За штатом, включая потенциальных заштатников |
| `is_soon_outstaff` | `=` | `1` | Скоро за штат |

Условия `is_outstaff_total` и `is_soon_outstaff` объединяются в ОДИН узел
`or`: в выборку попадают сотрудники, которые уже за штатом ИЛИ скоро за штат.
Весь or-узел соединён AND-ом с фильтром по статусу.

## Фильтры по категориям

Для получения нужной выборки накладывай дополнительные фильтры на результат
шаблона:

- «за штатом» = `is_outstaff_90_plus` = 1;
- «потенциальные заштатники» = `is_outstaff_less_90` = 1;
- «скоро за штат» = `is_soon_outstaff` = 1.

`is_outstaff_total` — это объединение `is_outstaff_90_plus` и
`is_outstaff_less_90`, поэтому в базовую выборку попадают и сотрудники за
штатом, и потенциальные заштатники.

Подгруппы для каждой категории (за штатом / потенциальные заштатники /
скоро за штат):

- с льготами = `has_active_benefit` = 1;
- декрет = `is_decree` = 1;
- внешние совместители = первый элемент массива `oshs.form_work_code` = "4".

Флаг «Особое внимание» (`is_special_attention`) уже рассчитан и лежит в
одноимённой колонке. Для фильтрации по этому признаку используй поле
`is_special_attention`.

---

## Типовые вопросы

- «Сколько у меня сотрудников за штатом?» — `is_outstaff_90_plus` = 1;
- «Кто находится за штатом дольше всех?» — сортировка по `days_outstaff`;
- «У кого критичный срок за штатом?» — группа «более 2 лет»;
- «Какие есть потенциальные заштатники?» — `is_outstaff_less_90` = 1;
- «Кто попадёт за штат в ближайшее время?» — `is_soon_outstaff` = 1.

## Правила обработки результата

### Категории и подгруппы

- Скилл возвращает активных сотрудников, находящихся за штатом (всего за
  штатом), потенциальных заштатников, скоро за штат, а также заштатных
  сотрудников с действующими льготами, декретников за штатом и внешних
  совместителей.
- Все категории льготников, декретников и внешних совместителей выводятся
  при условии `is_outstaff_total` = 1 (они должны быть на упраздненной
  штатной должности) или `is_soon_outstaff` = 1 (должность будет упразднена
  в ближайшие 15 дней).
- Разбивка по срокам нахождения за штатом использует готовое поле
  `days_outstaff`. Покажите распределение по группам: «менее 3 мес.»,
  «3-6 мес.», «6-12 мес.», «1-2 года», «более 2 лет».
- Распределение по льготным категориям стройте по полю
  `benefit_category_name` среди сотрудников с `is_outstaff_90_plus` = 1,
  при необходимости разложи строку на отдельные компоненты (льготы
  перечислены через запятую). Подсчитайте частоты и выведите количество
  сотрудников за штатом по каждой.
- Внимание: в выборку попадают только сотрудники, находящиеся за штатом
  (или скоро за штатом). Сотрудники с действующими льготами, декретом или
  внешние совместители, но не находящиеся за штатом, исключаются.

### Вывод детальных строк

- При детализации по сотрудникам выводите все поля, включая `work_mode`
  (режим работы). Трудовые договоры показывайте только те, у которых
  `contract_end_date` >= today().
- Поля `contract_type_name`, `contract_end_date`,
  `termination_requests.action_date`, `termination_requests.status_id`,
  `termination_requests.req_action_date` являются массивами. При выводе
  информации о сотруднике перечисляйте все значения этих массивов через
  запятую. Если требуется только одно значение, берите первый непустой
  элемент массива.
- При выводе полей `oshs.employee_id`, `oshs_director_full_name`,
  `hrbp_name`, `oshs.position_cancellation_start_date`,
  `oshs.form_work_code`, `oshs.unit_id`, `agile.unit_id` берем ВСЕГДА
  первый элемент указанных массивов.

### Поиск сотрудника по табельному номеру

- Если у вас есть `person_id` (UUID) из `get_employee_team`,
  `lookup_employee_by_name` или `get_employee_basic_profile`, сначала
  получите `employee_id` через профиль сотрудника. Затем сравните
  `employee_id` с полем `employee_id` (скаляр) или проверьте вхождение в
  массивы `oshs.employee_id` и `agile.employee_id`.

### Фильтрация по подразделению и другим разрезам

- Для фильтрации по подразделению используйте первый элемент массива
  `oshs.unit_id` (ID основного подразделения) и проверяйте, входит ли оно
  в первый массив массива `oshs.unit_id_tree` (дерево ID). Аналогично для
  agile: `agile.unit_id` входит в `agile.unit_id_tree`.
- Для фильтрации по функциональному блоку используйте поле `fblock_name`,
  по региону — `region_name`.
